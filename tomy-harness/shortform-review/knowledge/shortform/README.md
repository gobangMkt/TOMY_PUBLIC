# 릴스 분석 기록

릴스 기획·평가 스킬의 판단 기준. 원본에서 쌓아 배포한 것이라 여기서 고치지 않는다.
목표는 어떤 마케팅이 와도 터지는 릴스를 고르고 평가하는 판단력이다. 그래서 관찰 방식이 아니라 기획 순서대로 나눈다.

| 파일 | 내용 | 언제 읽나 |
|---|---|---|
| `목적.md` | 목적 판정 규칙(릴스·게시물 공통) | 분석·기획·평가 |
| `basics.md` | 기본기. 흔해서 차별화는 안 되지만 안 하면 손해 | 기획·평가 |
| `purposes/viral.md` · `inflow.md` · `follow.md` | 목적별 정의·성공 지표, 그 안의 템플릿(구간별 구성·작동 원리·사례) | 기획·평가 |
| `edges.md` | 엣지 인덱스(규칙, E번호표). 본문은 `edges/hook.md`(훅·증거), `edges/body.md`(본문 진행), `edges/ask.md`(요청·마무리) | 기획·평가, 트렌드 질문 |
| `expired.md` | 버릴 것. 효과가 끝난 방식 | 기획·평가 |
| `review.md` | 기획·평가 순서와 평가 출력 형식(팀원·서포터즈 릴스) | 기획·평가 |
| `reels/` | 외부 릴스 분석 원장. 1건=1파일 | 근거 확인 |

영상 파일은 레포에 두지 않는다.

## 템플릿 이름 규칙
`{목적}-{구조}`. 구조는 본문에서 시간을 가장 많이 차지하는 구성 단위 하나로 정한다. 걸치면 위에서부터 먼저 맞는 것.
| 구조 | 정의 |
|---|---|
| 재가공 | 이미 있는 원본(방송 등)을 세로 화면에 넣고 제목·로고를 덧입힘 |
| 서사 | 시작·전개·결말이 있는 이야기(상황극, 그림 컷, 경험담) |
| 리스트 | 항목을 번호나 순서대로 나열 |
| 워크스루 | 대상(앱 화면·공간·제품)을 직접 보여주며 따라감 |
| 한컷 | 한 장면, 또는 자막 하나에 묶인 같은 의미의 짧은 장면들이 본문 전부. 번호·순서 항목이나 전개가 없음 |

같은 템플릿 안에서 구간 구성이 둘로 갈리는 사례가 쌓이면 템플릿을 나눈다. 어느 템플릿에도 안 맞으면 새로 만든다.

## 층 이동
```
엣지 ──(여러 계정으로 퍼져 흔해짐)──> 기본기
엣지·기본기·템플릿 장치 ──(효과가 끝남)──> 버릴 것
```
버릴 것으로 내리는 근거는 셋 중 하나다.
- 같은 방식의 최근 사례가 연달아 성과가 떨어졌다(게시일 순 비교). 근거가 있으면 Claude가 제안하고 확정은 총괄.
- 고방만 하고 남은 안 한다(고방 필터).
- 총괄 판단.

"요즘 안 보인다"만으로는 내리지 않는다(학습용 표본이라 성공 편향). 내릴 때는 `expired.md` 행에 시점과 이유를 적고 원래 자리에서는 지운다.

## 파일 정리와 트렌드 질문
파일이 커졌을 때의 정리 기준과 트렌드 질문에 답하는 법은 스킬 SKILL.md가 정본이다.
