# 기획·평가 기준표

릴스를 기획할 때와, 팀원·서포터즈가 만든 릴스를 평가할 때 같은 순서로 본다. 기획은 위에서 아래로 정하고, 평가는 위에서 아래로 대조한다.

## 순서
| 단계 | 기획할 때 | 평가할 때 | 볼 파일 |
|---|---|---|---|
| 1. 목적 | 바이럴·유입·구독 중 하나를 정한다 | 영상과 캡션으로 목적을 판정한다. 목적이 하나로 안 읽히면(정보를 다 주고 마지막에 요청이 붙어 목적이 섞이는 등) 그것부터 지적한다 | `README.md` 목적 판정 규칙 |
| 2. 템플릿 | 목적 안에서 템플릿을 고르고 구간 구성을 따른다 | 고른 템플릿과 구간별로 대조해 빠지거나 어긋난 구간을 초 단위로 짚는다 | `purposes/` |
| 3. 기본기 | 빠짐없이 넣는다 | 빠진 것을 짚는다 | `basics.md` |
| 4. 버릴 것 | 쓰지 않는다 | 쓰고 있으면 짚는다 | `expired.md` |
| 5. 엣지 | 하나 이상 얹는다 | 있으면 무엇인지, 없으면 "차별점 없음"으로 적고 얹을 만한 것을 하나 제안한다 | `edges.md` |
| 6. 성과 | 목표를 정한다 | 모든 릴스에 팔로워 대비 조회수(바이럴 여부). 여기에 목적 지표: 유입=댓글÷좋아요·링크 클릭, 구독=팔로우 증가, 바이럴=공유·저장 | |

## 평가 출력 형식 (릴스 1건)
```
- 목적 / 템플릿: (판정 + 근거 한 줄)
- 판정: 통과 / 보완 / 재작업
- 잘한 점: 1~2개
- 고칠 점: 1~3개. 구간(초)을 지정하고 어떻게 바꿀지
- 다음에 얹을 엣지: 1개
- 성과: 조회수 ÷ 팔로워 (없으면 미확인)
```
- **통과:** 목적이 하나로 읽히고, 템플릿 구간이 맞고, 기본기 누락과 버릴 것이 없다.
- **보완:** 목적은 맞는데 구간 1~2개가 비거나 기본기가 하나 빠졌다.
- **재작업:** 목적이 섞였거나, 버릴 것을 쓰거나, 템플릿 구간 대부분이 어긋났다.

## 주의
- 서포터즈·팀원 계정은 팔로워 규모가 제각각이다. 조회수 절대값으로 서로 비교하지 않고 팔로워 대비 배수로 본다.
- 평가는 기록으로 남기지 않는다(답변용). 평가한 릴스를 학습시키라고 하면 그때 `reels/`에 저장한다.
- 엣지가 없다는 것만으로 재작업을 주지 않는다. 엣지는 가산점이다.
