# 상세페이지·랜딩 제작 키트 (마케팅팀장)

> 상세페이지(세일즈 랜딩·상품 상세·신청 페이지)를 **만들 때 맨 먼저 여는 파일**. 상세페이지 지식의 입구이고, 외부 레퍼런스 해부 원장은 별도 레퍼런스 원장에 쌓는다.
> 스크롤 연출(고정 화면 위 카드 쌓임·숫자 차오름)을 **구현**할 땐 별도 구현 레시피(코드·높이 실측) 레시피를 연다.
> 시각 완성도(간격·대비·컴포넌트)는 디자인 담당과 함께 본다.

## 0. 착수 전 4문 (답을 한 줄씩 적고 시작)

1. **멈칫 이유**: 고객이 이 CTA 앞에서 왜 멈추나? 실패 손실이면 고관여, 귀찮음·"굳이 지금?"이면 저관여다(`reference_marketing_funnel_psychology.md` "관여도 갈래"). 가격은 대리변수일 뿐이라 저가라도 실패 손실이 크면 고관여로 분류한다. 이게 가격 위치·긴급성 사용 여부·페이지 길이를 정한다.
2. **CTA가 파는 것**: 결제인가, 신청(무료)인가, 문의인가? 무료 신청 페이지는 고관여 상품을 팔기 위한 **저관여 첫 계단**일 수 있다(사례 A). 이 페이지가 넘길 다음 단계를 적는다.
3. **유입 채널**: 광고(메타·검색)로 들어오나, 플랫폼 탐색으로 들어오나? 광고 유입이면 소재 문구와 히어로 문구를 일치시킨다. 펀딩형(탐색) vs 커머스형(목적) 구분은 funnel_psychology "상세페이지는 유통 채널에 따라 다시 설계".
4. **증거 재고**: 지금 손에 있는 실물 증거(실측 수치·캡처·문서·후기)를 나열한다. 없는 증거 자리에 형용사를 넣지 않는다. 증거가 비면 페이지보다 증거 확보가 먼저다.

## 1. 생성 지시 (레퍼런스에서 뽑은 원리)

1. **숫자는 기준과 한 몸으로 쓴다.** 큰 숫자 바로 아래에 "무엇을, 언제, 누구 기준으로" 한 줄을 붙인다. 과장처럼 보일 숫자를 **정의로 방어**하고 기대치를 정직하게 둔다. 기준이 부끄러운 숫자면 쓰지 않는다.
2. **숫자 여러 개는 반론 순서로 배열한다.** 얼마나 빨리 → 나도 될까 → 얼마나 식으로 각 숫자가 다음 의심을 하나씩 지운다. 나열하기 전에 "고객의 의심 3개를 순서대로" 먼저 적는다.
3. **주장마다 실물을 붙인다.** 매출 주장 옆에 증빙 문서 캡처, 혜택 설명 자리에 형용사 대신 실제 정산 내역 UI를 둔다. **작은 실금액이 큰 약속보다 믿긴다.** 기능 안내도 같다: 기능 설명 문단 대신 그 기능이 만든 실제 화면(알림·카드·위젯)을 가상 인물 한 명의 데이터로 채워 보여준다. 같은 숫자가 여러 화면에 다시 나와야 한 사람의 이야기로 읽힌다(사례 C).
4. **문제를 "구조"로 재정의해 타깃을 넓힌다.** 여러 업종을 한 줄씩 나열해 "내 얘기"를 동시에 여러 명에게 만들고, "업종은 달라도 이유는 같다"는 재정의로 하나의 해법에 묶는다.
5. **메커니즘은 비교표 한 장으로.** 왜 되는지를 문단이 아니라 두 열("한 시간에 한 명" vs "동시에 수십~수백 명")로 보여준다.
6. **내용 예고는 목차 대신 "측정 지표"로.** 커리큘럼 대신 단계별 %와 KPI를 약속한다. 실무자 타깃이면 목차보다 지표가 전문성을 더 빨리 증명한다.
7. **CTA는 반복하되 문구는 하나.** 첫 화면·중간·혜택 뒤·마지막(또는 스티키 바)에 같은 문구를 둔다. 위치는 여럿, 말은 하나.
8. **혜택은 다음 단계 행동에 묶는다.** "신청만 해도"가 아니라 "라이브 참여자 한정"처럼 전환이 일어나는 곳까지 끌고 간다. 혜택을 설계할 때 "이 혜택이 어떤 행동을 만들게 하나"를 먼저 적는다.
9. **FAQ는 결제·가입 직전 반론과 법적 의무를 처리한다.** 자격·돈(정산·유형)·경제적 이해관계 표시 등 고객이 물어볼 것을 남기지 않는다.

## 2. 페이지 유형별 골격

| 유형 | 골격 | 근거 |
|---|---|---|
| **저관여 가입·신청형** (무료 가입, 파트너 모집) | 히어로(결과 숫자 1개 + 기준 각주 + CTA) → 반론 순서 숫자 3개 → "무엇인가요?" 4단계 타임라인 → 혜택 3개 각각 실물 UI 목업 → FAQ → 반복 CTA. 짧게(모바일 5,500px 내외) | 사례 B |
| **무료 웨비나·강의 리드형** (고관여 상품의 첫 계단) | 통념 선언 + 실물 증거 → 상품명·CTA → 문제(매출 0) → 업종 나열 → 구조 재정의 → 대비(1명 vs 100명) → 해결 질문 → 화자 스토리(한계→전환→수치→공식 문서) → 메커니즘 비교표 → 권위("아무한테나 배우지 마세요") → 측정 지표로 내용 예고 → CTA → 참석 한정 혜택 → 적용 대상 → 일시 → 최종 CTA | 사례 A |
| **기존 사용자 기능 출시·리뉴얼 안내형** (업데이트·시즌 오픈, 재방문 유도) | 감정 사진 히어로(캠페인명 + 한 줄 + 스크롤 안내) → 기능 3개를 각각 화면 고정 구간으로(영문 오버라인 + 얻는 것 제목 + 실제 UI 연출, 배경 흰·검 교차) → 나머지 기능은 가로 카드 5장 내외 → 마무리 문구 + CTA(내 기록 보기처럼 바로 새 기능으로) → 다음 화 예고. 본 CTA는 첫 고정 구간 뒤에도 한 번 | 사례 C |
| **고관여 B2B 상품 상세** (광고상품·SaaS) | 히어로(결과 카피 + 단일 CTA + 체험) → 소셜프루프(수치·로고·실명 인용) → Before/After → 기능 블록 지그재그 → 가격(정가·근거 병기) → 성과 사례 → 리스크 제로 배지 + 최종 CTA → FAQ | 사내 벤치마크 자료 채널톡 해부, 부동산 앱 정석 시퀀스는 같은 폴더 사내 자료 |

## 3. 출고 전 체크

- [ ] 모든 숫자 아래 기준(기간·대상·출처) 한 줄이 있다
- [ ] 히어로 문구가 유입 광고 소재 문구와 같은 약속을 한다
- [ ] 주장마다 실물(캡처·문서·실제 UI)이 붙어 있다. 형용사만 있는 혜택이 없다
- [ ] 날짜가 들어간 페이지면 지난 날짜가 남아 있지 않다(사례 A·C 결함, 2건 반복). 날짜 문구는 기한이 지나면 바꿀 문구까지 미리 정해 둔다
- [ ] 공유될 페이지면 og:image가 기본 이미지가 아니라 캠페인 전용이다(사례 C 결함)
- [ ] 스크롤 연출 페이지: 고정 구간 전환점에 빈 화면이 없다(여러 스크롤 위치에서 캡처로 확인), 본 CTA가 끝에만 있지 않다, 모션 줄이기 설정에서 최종 상태가 바로 보인다(사례 C)
- [ ] 반응형을 모바일·PC 이중 렌더로 만들었다면 제목(h1~h3)이 HTML에 두 번 들어가지 않았다(사례 C 결함)
- [ ] 빈 섹션이 노출되지 않는다: "아직 작성된 후기가 없습니다" 같은 빈 상태는 숨긴다(사례 A 결함)
- [ ] 핵심 숫자가 본문에 있다. 메타 태그에만 있으면 안 된다(사례 B 결함: 수수료 8%가 OG 설명에만 있고 본문엔 없음)
- [ ] 본문이 이미지 통짜가 아니라 텍스트다(검색·로딩·수정 비용). 통짜면 이유가 있다(광고 전용 noindex 등)
- [ ] 긴급성(마감·한정)은 실제로 있는 것만, 저관여 CTA에만
- [ ] 원가(열람비 등)를 단독 숫자로 노출하지 않았다. 단독 노출된 숫자는 그대로 가격 앵커가 된다
- [ ] 개수 경쟁에서 지는 상품이면 비교 축을 결과물로 할 수 있는 일로 옮겼다
- [ ] 할인 테스트는 정가 할인 표기가 아니라 유입별 쿠폰으로 설계했다(법적·측정 양면에서 안전)

## 4. 레퍼런스 사례

URL·유입 정보·캡처 경로·실측 금액·전체 흐름은 별도 레퍼런스 원장.

### 사례 A. 웨비나 수익화 무료 강의 신청 (고관여 상품의 저관여 첫 계단)
- 배울 것: 원리 3·4·5·6·7·8
- 결함: ①수집 시점에 라이브 일시가 지났는데 광고가 계속 돌고 있다 ②하단 "수강 후기: 아직 작성된 후기가 없습니다" 노출 ③본문 전체가 이미지(GIF)라 모바일 로딩이 무겁고 수정 때마다 재제작 ④강사 인물 컷 2장이 비슷해 두 번째 컷은 새 정보가 없다

### 사례 B. 쉐어링크 제휴 파트너 무료 가입 (저관여 가입형)
- 배울 것: 원리 1·2·3·7·9, 골격 "저관여 가입·신청형"
- 결함: ①핵심 조건인 수수료율이 OG 메타 설명엔 있고 본문엔 없다 ②히어로 숫자가 "최고치" 기준이라 각주가 있어도 기대치가 높게 잡힌다. 브랜드 신뢰가 있어 버티는 수준이고 무명 브랜드가 따라 하면 의심을 산다

### 사례 C. 플랩풋볼 "새로운 시즌" (기존 사용자 기능 출시 안내형)
- 배울 것: 원리 3(실제 UI를 가상 인물 데이터로), 골격 "기존 사용자 기능 출시·리뉴얼 안내형", 애니메이션 라이브러리 없이 스크롤 진행률 훅 하나 + IntersectionObserver로 만든 고정 구간 연출(레시피 별도 구현 레시피)
- 결함: ①지난 날짜 잔존 ②og:image 기본값 ③h2 이중 렌더 ④고정 구간 전환점 빈 화면 ⑤가상 인물 숫자 불일치 ⑥본 CTA가 13화면 끝 한 곳
