# 상세페이지·랜딩 제작 키트 (마케팅팀장)

> 상세페이지(세일즈 랜딩·상품 상세·신청 페이지)를 **만들 때 맨 먼저 여는 파일**. 흩어져 있던 상세페이지 지식의 입구이자, 외부 레퍼런스 해부 결과를 쌓는 곳.
> 시각 완성도(간격·대비·컴포넌트)는 디자인 담당과 함께 본다.

## 0. 착수 전 4문 (답을 한 줄씩 적고 시작)

1. **멈칫 이유**: 고객이 이 CTA 앞에서 왜 멈추나? 실패 손실이면 고관여, 귀찮음·"굳이 지금?"이면 저관여 → `reference_marketing_creative_and_copy.md` "관여도 갈래". 이게 가격 위치·긴급성 사용 여부·페이지 길이를 정한다.
2. **CTA가 파는 것**: 결제인가, 신청(무료)인가, 문의인가? 무료 신청 페이지는 고관여 상품을 팔기 위한 **저관여 첫 계단**일 수 있다(아래 사례 A). 이 페이지가 넘길 다음 단계를 적는다.
3. **유입 채널**: 광고(메타·검색)로 들어오나, 플랫폼 탐색으로 들어오나? 광고 유입이면 소재 문구와 히어로 문구를 일치시킨다. 펀딩형(탐색) vs 커머스형(목적) 구분은 creative_and_copy "상세페이지는 유통 채널에 따라 다시 설계".
4. **증거 재고**: 지금 손에 있는 실물 증거(실측 수치·캡처·문서·후기)를 나열한다. 없는 증거 자리에 형용사를 넣지 않는다. 증거가 비면 페이지보다 증거 확보가 먼저다.

## 1. 생성 지시 (레퍼런스에서 뽑은 원리)

1. **숫자는 기준과 한 몸으로 쓴다.** 큰 숫자 바로 아래에 "무엇을, 언제, 누구 기준으로" 한 줄. 토스는 "월 1,000만원"에 "최근 1개월 정산기간 중 가장 높은 월간 예상 수익금 기준", "3,100만원"에 "한 달에 200개 이상 공유한 분들의 판매금액"을 붙였다. 과장처럼 보일 숫자를 **정의로 방어**하고, 동시에 기대치를 정직하게 둔다. 기준이 부끄러운 숫자면 쓰지 않는다.
2. **숫자 여러 개는 반론 순서로 배열한다.** 토스: 얼마나 빨리(첫 수익 5일) → 나도 될까(10명 중 8명, 83.7%) → 얼마나(3,100만원). 각 숫자가 다음 의심을 하나씩 지운다. 숫자를 나열하기 전에 "고객의 의심 3개를 순서대로" 먼저 적는다.
3. **주장마다 실물을 붙인다.** 아마겟돈은 매출 주장 옆에 부가가치세 과세표준증명 캡처(2026.1.1~6.30 777,299,842원)를, 히어로엔 블러 처리한 실제 매출 장부를 깔았다. 토스는 혜택 "빠르고 투명한 정산"을 형용사 대신 실제 정산 내역 UI(생수 500ml 3건 32,300원)로 보여줬다. **작은 실금액이 큰 약속보다 믿긴다.**
4. **문제를 "구조"로 재정의해 타깃을 넓힌다.** 아마겟돈: 광고대행사·컨설턴트·보험설계사·변호사·병원을 한 줄씩 나열 → "업종은 달라도 이유는 같습니다 → 고객을 안정적으로 모으는 구조가 없기 때문". 나열로 "내 얘기"를 여러 명에게 동시에 만들고, 재정의로 하나의 해법에 묶는다.
5. **메커니즘은 비교표 한 장으로.** "일반적인 영업: 한 시간 동안 한 명에게 회사소개→문제진단→사례→전문성→상품" vs "웨비나: 동일한 과정을 수십~수백 명에게 동시에". 왜 되는지를 문단이 아니라 두 열로 보여준다.
6. **내용 예고는 목차 대신 "측정 지표"로.** 아마겟돈은 커리큘럼 대신 "광고(신청)→유입→참여(실시간)→구매(전환), 결국 이 4단계의 %를 어떻게 올리느냐"와 KPI 4개(CPA·입장률·전환율·참여율) 아이콘으로 다룰 내용을 약속했다. 실무자 타깃이면 목차보다 지표가 전문성을 더 빨리 증명한다.
7. **CTA는 반복하되 문구는 하나.** 아마겟돈은 첫 화면·중간·혜택 뒤·마지막에 "지금 (무료) 신청하기", 토스는 히어로·스티키 바·하단에 "시작하기". 위치는 여럿, 말은 하나.
8. **혜택은 다음 단계 행동에 묶는다.** 아마겟돈의 특별혜택 3종은 "신청만 해도"가 아니라 **"라이브 참여자 한정"**이다. 신청(저관여)에서 끝나지 않고 실제 참석(전환이 일어나는 곳)까지 끌고 간다. 혜택을 설계할 때 "이 혜택이 어떤 행동을 만들게 하나"를 먼저 적는다.
9. **FAQ는 결제·가입 직전 반론과 법적 의무를 처리한다.** 토스 FAQ 5개 중 2개가 자격(누가 가입 가능), 2개가 돈(정산일·사업자 유형), 1개가 공정위 경제적 이해관계 표시(권장 문구까지 제공). 고객이 물어볼 것을 남기지 않는다.

## 2. 페이지 유형별 골격

| 유형 | 골격 | 근거 |
|---|---|---|
| **저관여 가입·신청형** (무료 가입, 파트너 모집) | 히어로(결과 숫자 1개 + 기준 각주 + CTA) → 반론 순서 숫자 3개 → "무엇인가요?" 4단계 타임라인 → 혜택 3개 각각 실물 UI 목업 → FAQ → 반복 CTA. 짧게(모바일 5,500px 내외) | 사례 B 토스 |
| **무료 웨비나·강의 리드형** (고관여 상품의 첫 계단) | 통념 선언 + 실물 증거 → 상품명·CTA → 문제(매출 0) → 업종 나열 → 구조 재정의 → 대비(1명 vs 100명) → 해결 질문 → 화자 스토리(한계→전환→수치→공식 문서) → 메커니즘 비교표 → 권위("아무한테나 배우지 마세요") → 측정 지표로 내용 예고 → CTA → 참석 한정 혜택 → 적용 대상 → 일시 → 최종 CTA | 사례 A 아마겟돈 |
| **고관여 B2B 상품 상세** (광고상품·SaaS) | 히어로(결과 카피 + 단일 CTA + 체험) → 소셜프루프(수치·로고·실명 인용) → Before/After → 기능 블록 지그재그 → 가격(정가·근거 병기) → 성과 사례 → 리스크 제로 배지 + 최종 CTA → FAQ | 사내 벤치마크 자료 채널톡 해부, 부동산 앱 정석 시퀀스는 같은 폴더 사내 자료 |

## 3. 출고 전 체크

- [ ] 모든 숫자 아래 기준(기간·대상·출처) 한 줄이 있다
- [ ] 히어로 문구가 유입 광고 소재 문구와 같은 약속을 한다
- [ ] 주장마다 실물(캡처·문서·실제 UI)이 붙어 있다. 형용사만 있는 혜택이 없다
- [ ] 날짜가 들어간 페이지면 지난 날짜가 남아 있지 않다(사례 A 결함)
- [ ] 빈 섹션이 노출되지 않는다: "아직 작성된 후기가 없습니다" 같은 빈 상태는 숨긴다(사례 A 결함)
- [ ] 핵심 숫자가 본문에 있다. 메타 태그에만 있으면 안 된다(사례 B 결함: 수수료 8%가 OG 설명에만 있고 본문엔 없음)
- [ ] 본문이 이미지 통짜가 아니라 텍스트다(검색·로딩·수정 비용). 통짜면 이유가 있다(광고 전용 noindex 등)
- [ ] 긴급성(마감·한정)은 실제로 있는 것만, 저관여 CTA에만
