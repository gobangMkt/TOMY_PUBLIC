# 릴스 기획·평가 (팀 배포판)

실행 봇이 아니라, Claude가 이 스킬의 기준을 읽고 직접 판단한다. 기준은 전부 이 스킬 폴더 안 `knowledge/`에 있다.
이 배포판은 **기획과 평가만** 한다. 기준 파일을 고치거나 릴스를 학습시켜 쌓지 않는다(아래 "기준 갱신").

## 0. 처음 한 번: 도구 설치 (Windows)
릴스 링크를 직접 읽으려면 세 도구가 필요하다. 사용자에게 묻지 말고 없으면 설치한다.
1. 확인: `yt-dlp --version`, `ffmpeg -version`, `python -c "import faster_whisper"`
2. 없으면 설치:
   - `winget install --accept-source-agreements --accept-package-agreements yt-dlp.yt-dlp`
   - `winget install --accept-source-agreements --accept-package-agreements Gyan.FFmpeg`
   - `python -m pip install faster-whisper numpy` (python이 없으면 `winget install Python.Python.3.12` 후 진행)
3. 설치 직후 같은 터미널에서는 PATH가 안 잡힐 수 있다. `scripts/prep.sh`는 winget 설치 경로를 직접 찾으므로 그대로 쓰면 된다.
4. 받아쓰기 모델은 첫 실행 때 내려받는다(약 2분 반). 사용자에게 기다려 달라고 한 줄 알린다.

## 1. 릴스 읽기
1. 링크에서 릴스 ID를 뽑는다(`instagram.com/reel/{ID}/`).
2. `bash scripts/prep.sh <임시폴더> <ID> [<ID> ...]` 실행. 릴스마다 `meta.txt`(캡션·좋아요·댓글·게시일·댓글 앞 15개), `sheet.jpg`(장면 18칸), `hook_*.jpg`(처음 3초), `transcript.txt`(음성)가 생긴다. 임시폴더는 작업 폴더 밖 임시 경로를 쓴다.
3. `meta.txt`, `transcript.txt`를 읽고, `sheet.jpg`·`hook_*.jpg` 이미지를 직접 보고 시간순 구간표(구간 초 / 화면 / 자막·음성 / 역할)를 만든다. 처음 3초만 보지 말고 영상 전체를 본다.
4. 조회수와 팔로워 수는 메타에 없다. 사용자가 알려주거나, 인스타에 로그인된 브라우저로 그 계정 프로필의 릴스 탭에서 읽는다. 못 읽으면 "미확인"이라 쓰고 추측하지 않는다.
5. 다운로드가 실패하면(연령 제한·비공개) 사유를 말하고, 사용자에게 화면 캡처나 영상 파일을 달라고 한다. 우회하지 않는다.
6. 영상 파일은 분석에만 쓰고 끝나면 임시폴더째 지운다. 재게시하지 않는다.

## 2. 무엇을 읽나
| 요청 | 읽을 파일 |
|---|---|
| 평가 | `knowledge/shortform/review.md`(순서·출력 형식) → `README.md`(목적 판정 규칙) → 해당 `purposes/*.md` → `basics.md`·`expired.md`·`edges.md` |
| 기획 | 위와 같은 파일을 기획 순서로. 마케팅 대상의 타겟·포지션이 불분명하면 `knowledge/marketing/reference_marketing_strategy_and_targeting.md` 먼저 |
| 트렌드 질문 | `edges.md`의 사례 게시일, `reels/` 게시일을 시기별로 묶어 비교 |
| 근거가 필요할 때 | `knowledge/shortform/reels/`(외부 릴스 분석 원장) |

**마케팅팀장 지식(`knowledge/marketing/`)을 판단 근거로 쓴다.** 원본에서는 별도 마케팅팀장 인격이 맡던 판단이라, 배포판에는 그 지식을 함께 넣었다. 감으로 쓰지 말고 해당 절을 읽고 근거를 댄다.
- 훅 문장, 카피, 심리 트리거, 퍼널 단계(TOFU·MOFU·BOFU), 관여도: `reference_marketing_creative_and_copy.md`
- 누구에게 무엇을 팔지(STP), USP, 고객여정·퍼널 설계: `reference_marketing_strategy_and_targeting.md`
- 인스타 콘텐츠 유형별 역할: `reference_marketing_owned_channels.md`
- 다크패턴(과장 희소성·가짜 마감 등)은 심리 트리거 절의 경계선으로 걸러 지적한다.

## 3. 평가 (팀원·서포터즈가 만든 릴스)
`review.md`의 순서대로 대조한다: 목적 → 템플릿 → 기본기 → 버릴 것 → 엣지 → 성과.
- 목적은 바이럴·유입·구독 중 하나로 판정한다(판정 규칙은 `README.md`).
- 고칠 점은 반드시 구간(초)을 짚고 "어떻게 바꿀지"까지 쓴다. 근거는 템플릿 구간이나 마케팅 지식의 해당 절.
- 계정마다 팔로워 규모가 달라 조회수 절대값으로 비교하지 않는다. 팔로워 대비 배수로 본다.
- 출력은 `review.md`의 "평가 출력 형식" 그대로. 여러 건이면 건별로 쓰고 맨 끝에 공통으로 반복된 문제를 한 표로 묶는다.

## 4. 기획
1. 무엇을 마케팅하는지, 목적(바이럴·유입·구독), 올릴 계정을 확인한다. 셋 중 빠진 게 있으면 그것만 묻는다.
2. 목적 파일에서 템플릿 1~3개를 골라 초 단위 구간 구성으로 제시한다. 각 구간에 실제로 들어갈 화면·자막 문구 초안까지 쓴다.
3. 얹을 엣지 1~2개, 반드시 넣을 기본기, 피할 것을 붙인다.
4. 성공 지표(목적별)와 확인 방법을 적는다. 유입 목적이면 DM·프로필 링크에 UTM을 달도록 안내한다.

## 5. 쓰는 말
- 모든 판단에 [확인](영상·메타에서 직접 본 것) / [추정](해석)을 구분한다.
- 사례가 적은 템플릿·엣지(가설)는 가설이라고 말한다.
- 결과물 문구에는 AI 티 나는 상투어("획기적인", "완벽한", "~의 세계로")를 쓰지 않는다.

## 기준 갱신
이 스킬은 배포본이라 기준을 여기에 쌓지 않는다. 로컬에서 `knowledge/`를 고치면 다음 배포에서 덮어써진다.
평가하다가 **기준에 없는 새 방식, 기준이 틀린 사례, 성과가 크게 난 릴스**를 보면 결과 끝에 "기준 갱신 제안" 칸으로 따로 적어 둔다. 사용자가 그 내용을 원본 관리자에게 전달하면 원본에 반영돼 다음 배포에 들어온다.
