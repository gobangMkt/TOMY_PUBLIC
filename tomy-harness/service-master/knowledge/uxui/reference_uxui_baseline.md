# 출발선 — 새로 만드는 모든 화면의 기본값 (uxui)

## 이 파일이 존재하는 이유

총괄(2026-08-20): **"줍줍분양·어드민 등 굵직한 프로젝트를 완수하고 디자인 최종결론까지 냈는데, 이젠 뭘 만들든 최소 그 수준에서부터 시작이어야 하는 게 당연한 거 아니냐."**

맞다. 그동안은 "레퍼런스를 찾아보라"는 **지시**만 있었고 찾는 건 매번 새 숙제였다. 그래서 백지에서 다시 정하는 일이 반복됐다(07-17 어드민 5회 왕복, 08-19 찐정책 필터·IA 붕괴).

이 파일은 **이미 출시로 검증된 결론을 신규 기본값으로 못박은 것**이다.

> **사용법**: 새 화면·컴포넌트를 만들기 전에 이 파일부터 읽는다. 여기 있는 값은 **고민 대상이 아니라 기본값**이다. 벗어나려면 그 화면 고유의 사유가 있어야 하고, 벗어났으면 **그 자리에서 프로젝트 정본에 등록**한다.
> **출처 계층**: 규칙의 정본 = `사내 정본 문서` · 구현의 최신본 = `사내 구현 최신본` · 데스크톱 표 중심 별계 = `사내 별계 문서`(색·타이포는 공유 안 함, **동작→형태 어휘만** 상속).

## 1. 레이아웃 / 면

| 항목 | 기본값 |
|---|---|
| 기준 뷰포트 | 모바일 퍼스트 **375px** |
| 컬럼 | `mx-auto max-w-[560px] min-h-dvh` + `sm:border-x sm:border-hairline sm:shadow-frame` |
| 컬럼 밖 | `bg-canvas`(컬럼보다 짙게 → figure/ground 부양) |
| **섹션 구분** | **면분리. `border-t` 라인 금지.** 회색 배경(`paper-warm`) 위에 흰 밴드(`bg-paper`)를 쌓는다 |
| 밴드 간 gap | **12px**(`gap-3`) |
| 좌우 패딩 | `px-4` 고정 |
| 컬럼 배경 | 밴드를 쓰면 `paper-warm`, 안 쓰면 `paper` (밴드가 떠 보이려면 바닥이 회색이어야 한다) |
| 진입 카드 | 흰 카드 + radius 10 + `shadow-card` + `border-hairline` |
| 좌측 레일 | 목적지 3개 이상일 때만. 1개면 두지 않는다 |

**위계는 형태가 가른다** — 축이 다르면 담는 그릇이 달라야 한다. 홈 기준 확정형: 시간축 = 흰 밴드 위 평평한 세로 목록 / 분류축 = 회색 면 위 경계 있는 그룹 카드 + 가로 넘김. ⛔ **같은 형태를 두 겹 포개지 말 것**(슬라이드 안의 슬라이드, 2026-08-20).
**바(줄)를 새로 쌓지 않는다** — 역할이 같으면(목록을 좁히는 조건: 검색·필터·정렬) 기존 줄에. 폭이 모자라면 스크롤이 아니라 **줄만 나눈다**.

## 2. 색

| 토큰 | 값 | 용도 |
|---|---|---|
| `accent` / `accent-deep` | `#25B9B9` / `#10A6A6` | **단일 키컬러**(민트) / 테두리·체크·활성 도트 |
| `ink` / `ink-soft` / `ink-mute` / `disabled` | `#161B20` / `#555B61` / `#6D7379` / `#B1B6BC` | 본문 / 보조·보조링크 / 캡션·메타 / placeholder |
| `paper` / `paper-warm` / `canvas` | `#FFFFFF` / `#F5F6F7` / `#DFE3E8` | 면 / 면분할·칩 / 컬럼 밖 |
| `hairline` / `line` | `#ECEFF2` / `#E2E6EB` | 구분선 / 버튼·썸네일 테두리 |
| `open` / `wait`·`wait-ink` / `dday` / `caution` | `#1BAA5A` / `#F0A020`·`#B9791A` / `#FF513E` / `#D64B36` | 진행중·확정 / 예정(배경 14%+진한잉크) / **긴급도 축**(상태색과 별개) / 경고 문구 |
| `--shadow-card` / `--shadow-frame` | `0 0 10px rgb(0 0 0/.03)` / `0 1px 3px rgb(22 27 32/.05), 0 18px 50px -20px rgb(22 27 32/.18)` | |

1. **키컬러 = 내비게이터.** 민트는 ①주요 액션 ②활성·선택 상태 ③지도 마커에만. 카운트·보조 링크·랭크·정적 라벨·아이콘·마감은 전부 잉크.
2. ⛔ **카테고리별 고유색 금지.** 분류 구분은 색이 아니라 **형태**가 한다. 무지개 팔레트 = "긁어온 화면".
3. ⛔ **하드코딩 hex 금지** → `globals.css @theme` 토큰만. `text-white` 금지 → `text-paper`. (그물: `tests/design-tokens.test.ts` — **신규 프로젝트에 이 테스트를 같이 깐다**. 규칙만 있고 그물이 없으면 안 지켜진다.)
4. 판정·신뢰도 같은 새 축은 **새 색을 만들지 말고 기존 상태색을 재사용**. 반드시 **색 + 아이콘 + 텍스트 3종 페어링**(색약).
5. 두 축(예: 신청상태 / 자격판정)을 **같은 카드에 동시 렌더 금지**.
6. **BI 지정색이 대비 미달이면 채움을 흐리게 하지 말고 텍스트만 어둡게 한다**(실전 사례 승격, 2026-09-01). 네이버 그린 버튼의 흰 글자가 2.25:1로 미달일 때, 채움색을 어둡게 하면 4.5:1은 나오지만 "그 브랜드 특유의 밝은 톤"이 사라져 BI로 안 읽힌다 — 3안을 실제 화면에 나란히 띄워 판정한 결과 **채움은 원색 그대로 두고 글자색만 어둡게**(6.29:1)가 채택됐다. 원리: **BI가 요구하는 것은 채움색이고, 그 위에서 읽히는 글자색은 우리 몫이다**(카카오 노란 버튼이 검은 글자인 것과 같은 판단). 외부 브랜드색을 얹을 때 대비를 채움 쪽에서 맞추려 하지 말 것.

## 4. 컨트롤 어휘 — 동작의 종류가 형태를 정한다

| 동작 | 형태 | 규격 |
|---|---|---|
| ① 데이터를 **쓴다**(제출·발행·저장) | 키컬러 채움, 화면당 1~2개 | CTA 높이 **52px**, radius 8 |
| ② 같은 화면에서 **연다·더한다** | **테두리**(`border-line`) | |
| ③ **반복·부수**(새로고침·초기화) | **아이콘만 + `title`**, 라벨 금지 | 라벨을 붙이면 ②와 안 갈린다 |
| ④ **다른 화면으로 간다** | 텍스트 + 화살표, **테두리 금지** | `MoreLink` |
| ⑤ 조회 **조건을 고른다** | **드롭다운** (탭·세그먼트 펼치기 금지) | `SelectMenu` |
| ⑥ **상태를 보여준다** | 배지 | `StatusBadge` |
| ⑦ 제자리 **펼침** | 하단 풀블리드 텍스트 + Chevron | `MoreButton` |
| ⑧ **드릴다운**(행·타일 → 상세) | ChevronRight **16** | |

**핵심 대비: 테두리 = 여기서 처리된다 / 화살표 = 여기서 나간다.**
아이콘 역할 분리: **ChevronRight 16 = 드릴다운 / ArrowRight 15 = 전진 CTA.** 섞지 말 것.

## 5. 헤더 · 섹션 · 이동

| 요소 | 기본값 |
|---|---|
| **PageHeader** | `sticky top-0 z-20 h-12 flex items-center gap-1 border-b border-hairline bg-paper px-2`. 좌=BackButton / 제목 16px bold truncate(**`p` 태그** — 본문 h1과 충돌 방지) / 우=**전역성 컨트롤만**(로컬 기능은 콘텐츠 영역으로) |
| **SectionHeading** | `flex items-baseline gap-2 px-4 pt-5 pb-2.5`, h2 18px extrabold + `hint`(12px ink-mute) + `action` 슬롯. `level` 2/3, `tone` 점. ⛔ 로컬 h2/h3 손짜기 금지 |
| **제목 앞 점(tone)** | **상세 전용.** 밴드가 전부 '제목+본문'이라 형태로 못 가르는 화면에서 성격 표시. `accent` 점은 한 화면에 하나. 홈처럼 형태로 가를 수 있으면 쓰지 않는다 |
| **전체보기(MoreLink)** | 섹션 헤더 우측상단, 문구 **"전체보기" 고정**, 13px semibold `ink-soft` + ArrowRight 15 |
| **더보기(MoreButton)** | 리스트 하단 풀블리드, `더보기 N개`/`접기`, 13.5px semibold, Chevron 16, `py-3.5` |
| **BackButton** | ArrowLeft 20 sw1.5. `router.back()` 기본 + `fallback` 딥링크. ⛔ 하드 `href="/"` 금지 |
| **툴팁·팝오버(가독성 하한)** | **폭 288px · 폰트 13px · leading 1.5**가 하한. **항목이 2개 이상이면 불릿 리스트로 구조화**(점 마커 + 굵은 라벨 + 콜론), ⛔ em dash(`—`)를 라벨-설명 구분자로 쓰지 말 것. 참조 구현 `HelpTip.tsx`(찐정책) |

> 🚨 **툴팁 하한선은 BI와 무관하다**(2026-08-28 사용자 지시 *"툴팁 앞으로 무엇을 하던 이런식으로 해야함, BI는 달라질수있지만 가독성 쓰레기로 절대 만들지 않도록"*, 5건 대기 없이 즉시 승격). 색·톤·모서리·트리거 아이콘은 프로젝트마다 달라도 위 셋은 안 바뀐다.
> **원인이 폰트 크기 하나가 아니었다** — 248px·12px에 90자대 문단을 넣은 것이 ①글줄 길이 부족 ②**항목 경계를 시각 마커 없이 `\n`·"—"로만 표시**해 눈이 어디서 끊어 읽을지 못 찾음 ③em dash가 채움 문자처럼 읽혀 정보 구조를 숨김, 셋이 겹친 결과였다. ②③은 폭·폰트를 더 키워도 안 풀린다 — **구조화 자체가 해법이다.**
> **선호 추출(왜 리스트가 이기는가)**: 점 마커 + 굵은 라벨은 (a)항목 **개수를 즉시 세게** 하고 (b)라벨만 훑고 **필요한 항목만 골라 읽게** 한다. 문단은 "정의가 몇 개인지"조차 끝까지 읽어야 안다.
> ⛔ 구조가 필요 없는 단문까지 리스트로 갈아엎지 말 것 — 컴포넌트를 `text`(단문)/`items`(리스트) 두 모드로 나눈다.

## 7. 아이콘 — 두 어휘를 섞지 않는다

| 쓰임 | 어휘 | 규칙 |
|---|---|---|
| **기능 크롬**(화살표·돋보기·닫기·달력) | `lucide-react` | stroke **1.5~1.8**, 무채색 |
| **화면의 얼굴**(로고·파비콘·분류 배지·진입 타일) | **자체 SVG** | viewBox `0 0 20 20` · **fill 전용(stroke 금지)** · 플랫 · 색 5종 이내 |

자체 SVG 색은 hex가 아니라 `fill-accent`·`fill-paper` 토큰 유틸(`.svg` 파일만 예외). 3층 톤 `body`/`sub`/`cut`, muted면 전부 중립. ⛔ **UI 이모지 금지.** 로고는 심볼만 키컬러, 워드마크는 잉크.

| 🚨 치명 함정 | **드롭다운·팝오버가 든 컨테이너에 `overflow-*` 금지.** 한 축이 `auto`면 다른 축도 `visible`이 아니게 되어 팝오버가 통째로 잘린다(2026-08-19 필터 4개 전멸, 서버 로직은 멀쩡했다) |
| z-index | 헤더 `z-20` / 팝오버 `z-50` |

## 12. 퍼널·경로 도식 (2026-08-31 승격 — "앞으로 퍼널 관련 차트는 항상 이렇게")

> 총괄 지시(2026-08-31): *"앞으로 퍼널관련 차트 만들 때 항상 이렇게 하도록."* 아래는 줍줍분양 어드민 [방문 분석]에서 **세 번 고쳐 앉힌 결론**이다(세로 스택 → 가로 막대+화살표 → 좌→우 Sankey). 형태를 먼저 고르고 데이터를 끼워 맞추지 않는다 — **성격 판정이 먼저다.**

### 12-1. 형태는 성격이 정한다 (첫 질문: 좁아지기만 하는가, 갈래가 나뉘는가)

| 성격 | 형태 | 예 |
|---|---|---|
| **선형 퍼널** — 한 방향으로 좁아지는 단계 | 좌→우로 **이어지는 띠 + 갈라져 나가는 이탈 띠**(GA4 '유입경로 탐색' 그림). 다음 단계는 항상 같거나 낮다 | 방문 → 조회 → 클릭 |
| **분기형 경로** — 한 지점에서 갈리는 **같은 위계**의 선택지 | 뿌리 하나에서 **갈래가 갈라지는 좌→우 흐름**(GA4 '경로 탐색' 그림) | 예약버튼 → 공유하기 / 앱설치 |

⛔ **위→아래로 쌓는 세로 다이어그램 금지.** ⛔ **같은 크기 블록 + 화살표 금지**(단계 사이에 무엇이 얼마나 흐르는지를 그림이 못 말한다 — 그건 숫자를 읽어야 아는 것이고, 그러면 도식이 필요 없다).

### 12-2. 그림이 지켜야 할 계약

| 항목 | 규칙 |
|---|---|
| **띠 두께 = 그 양** | 이어지는 흐름의 두께 = 다음 단계 값, 이탈은 **줄어든 양만큼** 갈라져 바닥으로 빠진다 |
| 세로 배율 고정 | `preserveAspectRatio="none"` + viewBox 높이 = 실제 px 높이. **가로만 늘어나고 두께는 어떤 폭에서도 정확**해야 한다 |
| 노드는 SVG 아닌 **HTML div** | 위 설정이면 SVG 사각형은 폭까지 늘어나 화면마다 노드 굵기가 달라진다. 노드 폭 고정(9px), 높이만 값에 비례 |
| 🚨 **100% 초과는 clamp** | 값이 1단을 넘어도(한 방문이 여러 건 조회) **두께는 100%에서 멈춘다.** 초과 사실은 길이가 아니라 **옆의 % 숫자**가 말한다. ⚠️ 안 막으면 화면이 부서진다 — 찐정책 351%가 407px로 계산돼 상자를 뚫고 위 KPI 카드를 통째로 덮은 사고(2026-08-31) |
| **라벨 없는 도형 금지** | 노드마다 이름·값·**단위**, 단계 사이에 전환율·이탈(값·%). 단위가 섞이면(명 vs 회) 그 사실을 라벨에 적는다 |
| 판·가이드선 | 도식은 옅은 판(`bg-ink/[0.02]`) 위에 얹고 단계마다 세로 가이드선 — 어디까지가 그림이고 어디부터 라벨인지 갈라준다 |

### 12-3. 🚨 도식은 카드 폭을 얼추 채운다 (여백이 크게 남으면 그 자체가 결함)

같은 지적을 하루에 두 번 받았다(2026-08-31 *"둘 다 쓸데없이 width만 넓음"* → *"가로 폭이 짧으면 가운데 정렬 후 양옆으로 조금은 늘려서 폭을 얼추 채우도록. 지금 우측 여백이 너무 남잖아"*).

- ⛔ **노드 x를 고정 비율(`42%`)로 박지 말 것.** 카드가 넓어지면 오른쪽이 통째로 빈다.
- ✅ **컨테이너 폭·라벨 폭을 실측**해 배치한다(ResizeObserver + 라벨 ref). 라벨이 노드 오른쪽에 붙는 도식은 **라벨이 딱 들어갈 만큼만 남기고** 최대한 바깥으로 민다.
- ✅ **상·하한 clamp**로 좁은 폭에서는 예전 자리를 지킨다(라벨 잘림 방지). 참조 구현 `gobang-admin/src/components/bunyang/clarity-charts.tsx`의 `useFitWidth`.
- 그래도 도식이 카드의 절반도 못 채우면 **폭을 줄이는 게 답**이다 — 전체 폭 섹션 대신 2열(`lg:grid-cols-2`)로 나란히 둔다.
- 🚨 **선형 퍼널은 폭을 100% 채우더라도 전체 폭 섹션에 두지 않는다 — 도식이 하나뿐이어도 절반 폭이다**(2026-08-31 추가). 12-2의 두께 계약이 **세로 배율만** 고정하므로 가로가 2배면 **띠 기울기가 절반으로 눕는다** → 규격이 같은데 그림이 다르게 읽힌다(실측 열당 폭: 줍줍분양 401px 카드에서 120px vs 찐정책 813px 전체 폭에서 258px → 총괄 지적 *"분명히 줍줍분양에서 한 건데 지금은 생긴 게 다르잖아"*). **같은 도식은 같은 열당 폭에서 읽혀야 같은 도식이다.**
- 🚨 **오른쪽 빈 칸을 만났으면 "짝을 찾으라"는 뜻이지 "결함이 아니다"는 뜻이 아니다**(2026-09-01 정정 — 찐정책 퍼널을 절반 폭으로 내린 뒤 *"전환퍼널 옆에 width값 비는 거 뭔데… 불필요한 여백 생기잖아"* 재지적). "2열로 나란히 둔다"는 처방은 짝이 있을 때까지가 한 문장이다 — 짝 없이 절반 폭만 실행하고 "오른쪽은 페이지 배경이라 결함이 아니다"로 정당화하면 처방의 절반만 이행한 것이다. **짝 후보를 찾는 순서는 "형제 서비스엔 있는데 이 화면엔 없는 카드"부터다** — 없는 데이터를 지어내는 대신 이미 표로만 보여주던 값을 차트로 세우는 식으로(12-5의 "근거 없는 갈래 도식 금지"를 지키면서) 채운다. 이 순서를 타면 일관성 부채도 같이 갚힌다(형제 화면엔 있던 카드가 여기도 생긴다).

### 12-2-1. ⛔ 두께 분모를 최댓값으로 바꾸려는 유혹 (2026-08-31 실제 시도 → 되돌림)

2단이 1단보다 큰 서비스(찐정책 정책조회 487%)에서 clamp가 걸리면 **1·2단이 둘 다 100% 두께**가 되어, 그림은 "그대로 이어졌다"고 말하는데 라벨은 487%라고 말한다. 이걸 "도형이 숫자와 반대로 주장한다"고 보고 분모를 `max(값들)`로 바꿔 **띠가 넓어졌다 좁아지게** 만든 적이 있다(그 자체로는 그럴듯했고 1단이 최댓값인 줍줍분양은 렌더가 안 바뀌었다).

**그런데 그게 곧 "생긴 게 다르다"의 원인이었다** — 데이터에 따라 어떤 서비스는 좁아지는 계단, 어떤 서비스는 부푸는 혹이 되어 **같은 규격이 서비스마다 다른 그림**이 됐다. 퍼널은 *1단에서 얼마나 남았나*를 보는 그림이므로 **분모는 1단에 고정**돼야 여러 서비스를 나란히 읽을 수 있다. 초과는 % 숫자와 ⓘ가 말한다(12-2).

> **일반 원리**: 정확성(그림 하나의 정직함)과 **비교 가능성**(같은 규격이 어디서나 같게 읽힘)이 충돌하면, 도식 **규격**에서는 비교 가능성이 이긴다 — 개별 그림의 왜곡은 라벨·툴팁으로 고지한다. 규격을 데이터 사정에 맞춰 구부리면 그 규격은 더 이상 규격이 아니다.

### 12-4. 그릇은 옆 차트와 같은 카드

같은 성격의 도식은 **서비스가 달라도 같은 그릇**을 쓴다: 아이콘 배지 + **15px 제목** + ⓘ + **우측 범위 꼬리표**(그 도식이 덮는 기간·단위). ⛔ 회색 판(`bg-chrome`) + 13px h2 조합은 옆 차트 카드와 형태가 달라 '카드'로 안 읽힌다 — 찐정책 전환 퍼널이 혼자 그 상태로 남아 지적받았다(2026-08-31).

### 12-5. 데이터 계약 — 도형이 거짓말하지 않게

| 함정 | 규칙 |
|---|---|
| **기간이 다른 두 원장** | 서로 다른 소스를 한 퍼널에 넣을 땐 **두 원장이 함께 있는 날(교집합)만** 쓴다. 안 그러면 분모만 짧아 2단이 1단보다 커지고 비례 퍼널이 곧바로 거짓 도형이 된다(실측: 1,506 < 2,938 → 정합 시 1,506 → 790 → 211). 기준 기간을 **카드 머리에 박는다** |
| **근거 없는 뿌리** | 갈래가 그 뿌리에서 갈라졌다는 **계측 근거가 없으면 갈래 도식으로 그리지 않는다.** 찐정책 앱설치·공유는 신청클릭 뒤에 눌렸다는 정보가 안 실려서 안 그렸다 — 뿌리를 임의로 정하면 도형이 없는 인과를 주장한다 |
| **'나머지' 회색 띠** | 갈래가 뿌리의 **배타적 부분집합일 때만** 그린다. 한 사람이 둘 다 누를 수 있거나 다른 경로에서도 발생하면 `뿌리 − 갈래합`은 아무 뜻이 없다(라벨 없는 큰 도형이 틀린 주장을 한다) |
| **분모 명시** | 갈래의 %는 서로 비교하는 값이 아니라 **뿌리 대비 비중**이다(합이 100%를 넘을 수 있다). 그 사실을 ⓘ에 적는다 |

**참조 구현(그대로 이식 가능)**: `gobang-admin/src/components/bunyang/clarity-charts.tsx` — `ConversionFunnel`(선형) · `BranchFunnel`(분기) · `useFitWidth`(폭 채우기) · `barHeight`(clamp).
