# 토스 Simplicity 컨퍼런스 종합 — 서비스마스터 최상위 판단 프레임 (uxui)

출처: 사용자 제공 스크립트, 타임스탬프 있는 실제 영상 시리즈 11개 세션 전체 통합 (2026-07-14 수집·압축). ⭐서비스마스터 최상위 판단 인덱스 — 판단 요청은 먼저 아래 5대 법칙 중 분류 후 세부 사례로.

## 🏁 정의
"주니어는 화면의 표면(Surface)을 예쁘게 꾸미지만, 초씹고수는 유저의 무의식과 본능(Instinct), 비즈니스의 지표(Data), 그리고 법률적 프레임(System)의 역학 관계를 도구 삼아 물리적 마찰력을 지배한다."

---

## 법칙 1. "무겁다/답답하다"를 정량으로 쪼개는 기준 — 위계(Hierarchy)
한 화면에 모든 기능을 같은 무게감으로 노출하면 뇌 과부하. 빈도 1순위 액션만 전면 크게, 2~3순위는 뎁스 뒤로 숨길 것.

- **결제단말기(류관준)**: 카드투입구·마그네틱·NFC·QR이 한 화면에 몰려 혼란 → 빈도 1위(IC카드+디스플레이) 전면배치, 마그네틱은 후면 측면 은닉(자연스럽게 올바른 방향 유도), NFC는 옆면. 브랜드컬러(토스블루)도 참아서 위계 지킴 — 기기가 튀면 디스플레이 속 소프트웨어 중요도가 흩어짐.
- **포스기(박지영)**: 메뉴선택·결제수단·결제가 한 화면에 몰려 알바 잦은 실수(30~40만원 손해) → 액션 단위 스텝바이스텝 분절, 학습 없이 결제 가능하게.
- **내문서함 해체(이지윤)**: 콘웨이의 법칙 함정 — 조직구조(한 팀이 등본·과태료·관리비 다 담당)를 그대로 화면에 투영해 복잡해짐. "설명 가이드 화면이 필요하면 이미 실패"라는 신호. 해법: 화면단위가 아닌 **행동(Action) 단위**로 해체(발급받기/납부하기/알림받기) → 각 탭에 재배치. PO 설득은 "장기적으로 유저가 이해 못하는 화면은 이탈한다"는 장기가치로.

## 법칙 2. "편리함이 무조건 최선은 아니다" — 매몰비용과 능동 UX
완전자동화가 오히려 이탈을 만들 수 있음. 단, **성취감을 주는 소비자 행동**과 **순수 반복업무**는 정반대로 판단할 것.

- **토스뱅크 이자수령(허소임)**: 이자공유 8배 급증 데이터에서 "매일 확인하는 희열"을 포착 → 자동지급(안A) 대신 유저가 직접 누르는 수동수령(안B) 채택. 시각적파괴시뮬레이션(자동지급 시 거래내역 90% 도배)+학술근거(나쁜 자동화=Noise)로 타직군 설득. 실시간 소수점 증가+CTA 손맛(이펙트·사운드)으로 도파민 강화.
- **가입플로우(임경은·임지영)**: 전화번호 자동입력 제거(마찰↑)했더니 오히려 약관동의율·완료율 상승 — 너무 쉽게 가입되면 투자한 에너지(매몰비용)가 적어 중간포기가 안 아까움. 단, "왜 인증이 필요한지" 맥락 설명 인트로가 있어야 함(시니어 유저 불안 해소).
- **판단기준 확정**: 성취감 주는 소비자 대상 행동 → 마찰 유지 고려 / 순수 반복업무(내부툴 등) → 완전자동화가 정답. **위험기반 마찰 제어**: 실수 대가가 큰 구간(계좌연동 비밀번호 최종시도)은 의도적으로 마찰↑(경고·강제전환), 그 외는 마찰↓.
- **계좌연동 재설계**: 168개 예외 산 전체 제거 판단. 비밀번호 오류 3단계 리스크 제어(초기오류 안내→실패값 매몰비용 재활용해 재설정 스킵→최종기회는 강제 경고전환). ⚠️ 이건 위 "매몰비용 배신"과 반대방향(완주율 유지 아니라 효율 위한 재활용)이라 혼동 주의. 계좌번호 기억 못하는 유저를 위해 과거 송금기록 역추적 → 빈도·볼륨·최신성 3지표로 랭킹 추천, 타이핑 없이 터치 한 번 연동.
- **내부툴 대조사례**: 사내 권한신청 시스템(신청/완료 2단어 압축, 시스템이 아는 정보 안 물음, 슬랙봇 승인, 직군별 프리셋 자동화 0초승인) → 2,600시간 절약. 이건 성취감 불필요한 순수효율 영역이라 완전자동화가 옳음.

## 법칙 3. "말보다 행동(Action)과 현장(Field)에 답이 있다"
유저는 말로 물으면 익숙함에 갇혀 거짓말("불편한 거 없다")함. 현장 관찰·게릴라 테스트가 유일한 해법.

- **장부관리 리서치(박지희)**: 리크루팅 안 되면 유저의 온라인 서식지(카페·오픈채팅)로 잠입해 조회수 높은 글 분석. 질문 범위를 "매출·매입 두 가지"로 극도로 좁힘(5명 만에 조사 중단하고 재설계). "노하우 공유" 컨셉으로 화면공유 요청 — 말이 아니라 실제 엑셀 흔적을 봄.
- **포스기 관찰(박지영)**: "불편한 거 없다"는 답변 → 매장 상주 관찰로 진짜 결함 발견. 디자이너 직접 앞치마 매고 알바 근무 → 팝업UI가 실제 피크타임엔 복잡한 동선임을 체감, 토글스위치로 전환.
- **접근성 이벤트(김유라·구슬)**: 스크린리더 최적화가 비장애인 화면구조에선 실패 → 두 유저층 화면을 기술적으로 과감히 분기(비장애인=매끈한 원퍼널, 시각장애인=1페이지 1줄 가이드 10퍼널). "특별하다"는 표현 자체가 무의식적 차별 — 전문가 피드백으로 전량 제거.
- **네온카드(최민수)**: 공급자의 '멋부린 의미'(코발트광석 컨셉 등) 참패 → 유저 직관(투명 플레이트)으로 전환. 인쇄 채도 한계는 공장 직접 방문해 잉크배합 역계산.
- **리서처 Q&A**: 유도질문 회피(❌"이해 쉬우셨죠?" / ✅"어떤 부분에서 이해 쉬우셨나요?"). 정량(설문)=이탈 이유 비중을 숫자로 확인할 때, 정성(인터뷰·UT)=왜 머뭇거리는지 맥락 알고 싶을 때. "데이터는 숫자만 말하고 이유는 관찰해야만 나온다."

## 법칙 4. "협업의 간극을 기술 시스템(Frame)으로 파괴할 것"
말로 잔소리하는 건 하수. 코드가 바로 꽂히는 공통 시스템을 설계하는 게 고수.

- **인터랙션 설득(김지혜·박연지)**: "예쁘잖아요" 대신 지표(대출대기화면 이탈률↓·도달률↑)로 설득. 개발 불가 시 눈속임(페이드 레이어)으로 대안. 모션 토큰화('스프링킥' 등)+자체 라이브러리 'Rally'로 코드 스펙을 피그마에 바로 얹음.
- **Framer 전사전환(TDS팀)**: 정적 드로잉 툴(피그마)은 "버튼모양 스티커"일 뿐 → 코드기반 Framer로 전면 이전, 실제 살아있는 컴포넌트로 디자인. 오퍼레이션: 온보딩30회+, 이슈500개+ 해결, 네덜란드 본사와 1주만에 커스텀 핸드오프 구축. 지능형 컴포넌트: 실시간 텍스트포맷터, 통합에셋검색(3000개+).
- **UX라이팅 시스템(김상훈)**: Do&Don't 구체화(이모지 과용금지 등). **Losing Pattern(지는패턴) 규격화** — 잘되는 패턴만 정리하지 말고 "절대 쓰지 말 것" 목록을 먼저 분류해 실무 고민시간·A/B비용 절감.
- **보이스톤 린트 시스템(초대 UX라이터)**: 디자이너별 제각각 말투(송금완료/성공했어요/보냈어요) → 가이드 문서는 아무도 안 봐서 레거시화 → **"안 지키면 작업 자체가 불편해지는 시스템"**으로 전환, 개발자 린터 원리를 Framer에 이식. 단순치환 실패 방지 위해 명사군(1:1치환)과 동사군(문맥별 확장템플릿) 분리 설계 → 2주 만에 8,000개+ 규칙 DB, 구글시트→API→Framer 실시간 동기화.
- **그래픽 공학(류OO 등)**: 반사광(3D그래픽+고정CTA컬러 일체화), APNG포맷(다크모드 대응+MP4보다 경량, 렌더링 재작업 제거), 타임라인병합(여러 인트로화면을 하나의 3D루프+오퍼시티 크로스페이드로), 리소스센터-CDN 1:1 강제동기화(안 거치면 개발반영 자체가 안 됨).
- **핵심 철학**: 예쁜 시안 하나보다 재사용 가능한 구조(컴포넌트)·규칙(토큰)을 심는 것이 고수의 자격.

## 법칙 5. 인터랙션이 본능과 규제를 다루는 법
- **연속적 여정**: 화면전환의 '점과점' 단절 대신 스크롤과 텍스트·영상을 유기적으로 연동 → 다음 컷을 본능적으로 보는 도파민 루프, 이탈 감소.
- **숫자 롤링 애니메이션**: 증가=좌측시작+위로확장(상승쾌감), 감소=우측시작+아래로축소. 폭변화(콤마생성) 자동연산으로 좌우비대칭 방지. 라이브러리화해 코딩없이 전사 적용.
- **밀어서 동의하기**: 보험 약관 규제(전부 읽게 강제)를 하수는 체크박스로 대충 처리 → 고수는 TTS속도-스크롤 1:1매핑+**"밀어서 수동 동의"** 제스처(물리적 마찰=심리적 의지 인지 강화) → 법 준수+혁신금융서비스 지정 통과.

## 부록: 프로덕트 윤리
- **긍정형 가이드**: "하지 말라"는 반발/미인지, "이렇게 하자"는 긍정형이 효과적(스키선수 비유: 나무를 피하라 vs 길을 따라가라).
- 다크패턴 경계는 [[reference_uxui_writing_system]] §다크패턴 경계선(판정 질문 3개)에서 판정한다.

## 부록: 인간화된 라이팅(Humanized UX) — 텍스트가 화면의 30~40% 차지
1. **해피모먼트 증폭**: "대출상환완료" 대신 "그동안 고생 많으셨어요", 생일축하 메시지 → 자발적 바이럴
2. **VOC 기반 정직한 위로**: "한도 100만원 상향" 대신 "그동안 불편했을 것 같아요, 이제 늘렸어요"
3. **불안 선제방어**: 약관동의 화면에 기능상 불필요해도 "그 마음 잘 알아요, 걱정 마세요" 문장 집요하게 추가
- 판단잣대: 설명서 필요한 기획 버리기 / 유저의 감정적 타이밍(기쁨·불안·짜증) 1순위 계산 / 공급자 언어(개설·에러코드501) 대신 인간의 언어(만들기·문제가 생겼어요)

## 서비스마스터 적용 순서
1. 판단 요청 → 위 5대 법칙 중 분류
2. 해당 법칙의 사례·수치 근거 확인
3. [[reference_ux_judgment_lenses]]의 3대 렌즈(마이크로)+구조적판단기준(매크로)으로 화면단위 진단
4. 결론은 감이 아니라 지표/시뮬레이션/근거로 뒷받침
