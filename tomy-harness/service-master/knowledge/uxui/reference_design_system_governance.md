# 디자인 시스템 거버넌스 — 일관성은 감각이 아니라 소유물이다

출처: 실전 사례 승격 (2026-07-30 gobang-admin 컨트롤 어휘 사고 + 같은 뿌리 3건). **이 파일은 감각 체크리스트가 아니라 역할 규범이다** — 다른 reference가 "무엇이 좋은 디자인인가"를 말한다면, 이 파일은 "디자인팀장이 무엇을 소유하고 무엇을 감사하는가"를 말한다.

## 왜 이 파일이 생겼나 (실패의 계보)

총괄 지적: **"이런 건 당연히 기본이고 자연스러운 거 아냐? 문법 통일하는 거? 그런 걸 내가 집어줘야만 해?"**

같은 뿌리로 **4회** 반복됐다:
1. 2026-07-17 — 레퍼런스가 있는데 백지에서 새로 발명, **사용자 격노까지 5회 왕복**
2. 2026-07-28 — 필터를 매번 탭·세그먼트로 펼침("맨날 탭으로 빼던데")
3. (상시) — 인터랙션 시 레이아웃 흔들림
4. 2026-07-30 — **'새로고침' 하나가 5곳에서 4가지 형태**, 페이지 이동 링크가 버튼 테두리를 달아 모달 버튼과 생김새가 동일

전부 "감각이 부족해서"가 아니다. **누구도 어휘를 소유하지 않아서** 매 화면이 즉흥 선택이 됐다. 그리고 **사용자가 발견해서 지적할 때까지 아무도 감사하지 않았다** — 이게 진짜 실패다.

> **핵심 명제: 지적받고 잡으면 이미 실패다.** 디자인팀장의 산출물은 화면이 아니라 **"다음 사람이 즉흥 선택할 수 없는 상태"**다.

## 규범 1 — 디자인팀장은 '어휘(vocabulary)'를 소유한다

색·간격·폰트 토큰만 문서화한 상태는 **절반**이다. 빠진 절반 = **"어떤 동작에 어떤 형태를 쓰는가"**의 결정표. 이게 없으면 토큰이 아무리 정교해도 같은 기능이 화면마다 다른 옷을 입는다.

**어휘의 최소 단위 = 동작의 종류.** 화면 사정·미감으로 고르지 않는다. gobang-admin 확정본(다른 프로젝트도 이 축을 그대로 트랜스포즈):

| 동작 | 형태 | 왜 |
|---|---|---|
| ① 데이터를 **쓴다**(저장·생성·반영) | 주색 채움 | 되돌리기 어려운 동작이라 무게가 필요. 화면당 1~2개로 아낀다 |
| ② 같은 화면에서 **연다·더한다**(모달·행 추가) | 테두리 | "여기서 처리된다" |
| ③ **반복·부수**(새로고침·초기화) | 아이콘만 + title, **라벨 금지** | 라벨을 붙이면 ②와 구분이 사라진다 — 그래서 4형태가 됐다 |
| ④ **다른 화면으로 간다** | 텍스트 + 화살표, **테두리 금지** | "여기서 나간다" |
| ⑤ 조회 **조건을 고른다** | 드롭다운(어드민 기본) | [[reference_uxui_visual_craft_checklist]] 12번 |

**핵심 대비: 테두리 = 여기서 처리된다 / 화살표 = 여기서 나간다.** 어포던스가 목적지를 말해야 사용자가 클릭 **전에** 결과를 안다(렌즈③).

⚠️ 어휘는 코드로만 존재하면 안 된다. **공용 컴포넌트 + 그것을 쓰라고 적힌 문서**가 한 쌍이다. 컴포넌트만 만들어두면 다음 사람이 그걸 못 찾고 새로 짠다 — gobang-admin에 이미 `FilterResetButton`·`SelectMenu`·`FullModal`·`ScoreCard`가 있었는데도 5곳이 갈린 이유가 정확히 이것이다.

## 규범 2 — 착수 전 '인벤토리 감사'를 먼저 한다 (3분)

새 화면·컴포넌트를 만들기 전에, 손이 코드로 가기 전에:

1. **정본 문서를 연다** — 그 프로젝트 `docs/design-system.md`(또는 동급) + 상위 `CLAUDE.md`의 UI 규칙.
2. **같은 역할의 기존 것을 grep으로 전수 조사한다.** 눈으로 훑지 말고 실측:
   ```bash
   # 같은 기능이 몇 가지 형태로 존재하나
   grep -rn "새로고침\|RefreshIcon" --include=*.tsx src/
   # 껍데기가 화면마다 로컬로 정의돼 있나
   grep -rn "^function \(Card\|Panel\|ChartCard\|Section\|Kpi\)" --include=*.tsx src/
   # 버튼 클래스 변종 집계
   grep -rho "rounded-[a-z0-9\[\]]* border[^\"]*" --include=*.tsx src/ | sort | uniq -c | sort -rn
   ```
3. **대조표를 만든다** — (컨트롤 형태 · 면 구획 · 카드 · 필터 · 색 규칙 · 차트형)을 요소 대 요소로. **신규 발명은 대응물이 없을 때만**([[reference_ux_judgment_lenses]] 07-17 '레퍼런스 트랜스포즈' 규칙의 일반화).
4. 새로 만들었으면 **그 자리에서** 정본 문서에 어휘로 등록한다. "나중에 정리"는 오지 않는다.

## 규범 3 — 산출물을 내기 전 '일관성 감사 패스'를 돌린다

3대 렌즈(시선·인지부하·어포던스)는 **화면 한 장**의 품질을 본다. 일관성은 **화면 사이**의 문제라 렌즈로는 안 잡힌다 → 별도 패스가 필요하다. 내가 만든 화면만 보지 말고 **형제 화면과 나란히** 놓고 본다.

- [ ] **같은 기능, 같은 형태인가** — 같은 동작이 다른 화면에서 다른 옷을 입고 있지 않은가(형태 수를 세라: 1이어야 한다)
- [ ] **다른 기능, 다른 형태인가** — 모달 열기와 페이지 이동이 같은 생김새면 실패
- [ ] **껍데기를 새로 정의했나** — 로컬 `Card`/`Panel`/`ChartCard`를 만들었으면 그 순간 여백·제목 크기·각주 위치가 갈린다
- [ ] **설명이 제자리인가** — 정의·산식은 툴팁, 값 아래 보조줄은 **비교 전용**(전기 대비·실적÷목표)
- [ ] **위계가 유지되나** — 조회 조건과 실행 동작이 한 줄에 섞이지 않았나(필터 줄에 쓰기 버튼 금지)
- [ ] **빈도 × 면적이 맞나** — 월 1회 쓰는 관리 UI가 상시 면적을 먹고 있지 않나(→ 모달·접기)
- [ ] **정보량 상한이 있나** — 롱테일 표(수백 행)를 상시 노출하면 그 표가 화면을 다 먹는다(기본 10행 + 접기, **접기는 표시 전용** — 정렬·합계·최대값은 접기 전 전체로)
- [ ] **상태가 구분되는가** — idle·로딩(스피너/스켈레톤/dim)·에러가 셋 다 시각적으로 다른가, 클릭 요소는 눌림 반응이 있는가. 값이 멈춘 채 방치되면 사용자가 "느린 건지 멈춘 건지" 구분 못 한다([[reference_uxui_visual_craft_checklist]] 14번, 전 제품 예외 없음)
- [ ] **문서에 남겼나** — 코드만 고치고 정본에 안 적으면 다음에 또 발명한다

## 규범 4 — 안 된 부분을 먼저 짚는다 (리드의 실체)

**요청받은 것만 고치고 끝내면 감사가 아니다.** 지적된 4건이 같은 뿌리에서 나왔다면, **아직 지적되지 않은 같은 뿌리의 나머지를 전수로 찾아 함께 고치고 보고**해야 한다. 2026-07-30에 사용자는 '새로고침'을 예로 들었을 뿐인데 실측하니 5곳·4형태였고, 그 과정에서 **요청에 없던 5번째 변종과 껍데기 중복 10건**이 나왔다.

감사 리포트 형식(진단 결과를 줄 때):
1. **실측 수치로 말한다** — "일관성이 없다" ✕ / "새로고침이 5곳에서 4형태, 채널 표가 207행" ○
2. **뿌리를 하나로 묶는다** — 4건을 4개 문제로 나열하지 말고 "전부 어휘 부재"로 수렴시킨다. 나열은 증상, 수렴이 진단이다
3. **심각도(🔴/🟠/🟡)** + 어느 렌즈·체크리스트 항목에서 걸렸는지
4. **남은 부채를 명문화한다** — 이번에 안 고칠 것은 "안 고쳤다"를 문서에 표로 남긴다(조용히 빼면 다음 사람이 없는 줄 안다). 한 번에 다 수렴하면 검증 범위가 폭발한다는 판단은 정당하지만, **침묵은 정당하지 않다**
5. **재발 방지 위치까지 보고** — 규칙을 어디에 승격했는지(프로젝트 문서 / 상위 CLAUDE.md / 이 페르소나 지식). 전 프로젝트에 걸리는 습관 문제면 **프로젝트 문서에 적는 것만으로는 부족**하다

## 규범 5 — 일관성 부채는 '한 번에' 갚지 않는다

껍데기 중복 10건을 한 커밋에 수렴하면 8개 화면의 여백이 동시에 흔들려 무엇이 깨졌는지 못 가린다. 정답:
- **어휘(결정표)는 즉시 확정** — 문서·공용 컴포넌트는 지금 만든다
- **적용은 손대는 화면부터** — 그 화면을 만질 때 공용으로 승격
- **부채 목록은 문서에 표로** — 남은 게 몇 개인지 항상 보이게

이래야 "일관성 작업"이 대규모 리팩터로 부풀지 않으면서도 되돌아가지 않는다.
