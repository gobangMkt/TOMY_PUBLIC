# 토스 서비스 설계 원칙 4가지

출처: toss.tech 아티클 4편 (2026-07-14 수집). designer-onboarding 아티클은 조직 온보딩 주제라 제외(서비스마스터 소관 아님).

## 1. 입력 최소화 4원칙
"사용자 1초 절약 = 월 1,437만 명 누적 약 6개월" — 입력 필드 마찰 제거 구체 패턴.
1. **단일 선택 화면엔 CTA 제거** — 정보 하나 고르고 나가는 화면은 확인버튼 자체를 없앰
2. **자릿수 고정 필드는 CTA 생략** — 주민번호·휴대폰번호처럼 길이가 정해지면 자동 진행
3. **입력 유형에 맞는 키보드 기본 세팅** — 인증번호 입력인데 한글 키보드면 실패, 숫자 키보드로 미리 세팅
4. **Focus 상태로 진입** — 페이지 진입 시 키보드가 이미 올라와 있어 추가 클릭 불필요

⚠️ **예외 주의**: 이 원칙은 "정보 조회·단순 입력" 상황의 기본값. 그 행동 자체가 성취감을 주는 경우(이자 수령 등)엔 오히려 마찰을 남기는 게 맞을 수 있음 — [[reference_simplicity_conference_synthesis]] 법칙2(성취감 주는 행동은 마찰을 남긴다) 참고.

## 2. "우리에겐 당연해도 사용자는 아니다" (Curse of Knowledge 실전판)
메이커에게 당연한 UI가 사용자에겐 낯설 수 있음 — Curse of Knowledge의 실전 사례. 생성측 대응은 [[reference_uxui_winning_design_principles]] 원리1(익숙함이 새로움을 이긴다).

- **사례1**: 서랍처럼 끌어내리는 달력 인터랙션 → 사용자가 존재 자체를 인식 못 함 → 익숙한 "탭" UI로 변경 → **이용률 4배 증가**. 교훈: 특별한 UI보다 누구나 떠올릴 수 있는 UI가 이김.
- **사례2**: 메모 기능을 고객센터 문의/송금 메시지로 오해 → "나만 볼 수 있는 메모" 문구 추가로 해결
- **경고 신호**: "이건 당연히 알겠지", "일단은 이렇게", "원래 어려운 개념이라", "빠른 실험이니까" — 이 말이 나오면 공급자 관점에 빠진 것
- **강화법**: 의식적 노력 + 직접 사용자 관찰·패턴 분석이 유일한 해법

## 3. "문제 원인의 원인을 찾아서" (근본원인 분석 방법론)
법인카드 영수증 마감 미제출 40% → 원인의 원인까지 파고들어 자동화·선택지 최소화로 **5%까지 감소**.
- 방법론: "왜?"를 반복 질문 — 겉보기 증상(제출 안 함) 너머 진짜 설계결함(과정이 불편해서 미룸) 발견
- 해법 패턴: 결제처 기반 자동분류(음식점→식대 자동선택), 자유입력 대신 선택형(동료 이름 리스트), 반복 데이터 시스템이 자동 처리(택시 선결제·심야 교통비 자동분류)
- 감이 아니라 데이터+관찰로 원인 특정 — 판단을 내렸으면 "이걸 검증하려면 어떤 데이터·실험이 필요한가"를 항상 덧붙인다

## 4. Easy to Answer — 판단을 요구하지 말고 사실 확인을 요구하라
(2026-08-20 `reference_toss_easy_to_answer.md` 흡수 — 파일 하나 분량이 아니었다)

**3초 내에 답이 안 나오면 너무 어려운 질문**이다. 병원비 청구 퍼널에서 *"전문가 도움받을래, 직접 할래?"*(판단 요구)를 **"서류 있어?"**(사실 확인)로 바꾸자 **이탈률 50%p 감소**. 선택 후 무슨 일이 벌어질지 예상할 수 없는 질문이 이탈의 원인이었다.
- 부수 개선: 보험사 목록 전체 → **가입된 것만** 노출(고를 것을 줄인다).
- 실무 체크: 질문형 UI(선택지·폼 필드)를 만들 때 **"사용자가 판단 없이 즉답할 수 있는가"**. 기능을 더하는 것보다 막힘을 재설계하는 쪽이 전환율에 크게 기여한다.

## 5. Value First, Cost Later
비용(입력·인증 등) 요구 전에 얻을 가치를 먼저 보여줌.
- **사례**: 보험조회에 인증 4단계 필요 → 실제 정보 보기 전 이탈 다발 → 더미데이터로 "보험료 비교 그래프", "또래 비교"를 먼저 보여줌 → **조회완료율 67% 증가**
- **비용 판단 체크리스트**: 질문 3~4개 이상이면 지침, 5초 내 답 어려우면 고민 유발(위 §4와 같은 결), 민감정보 요청은 거부감 상승
- 결론: 긴 과정이 필요하면 그만큼 가치를 먼저 보여줘야 사용자가 완주함
