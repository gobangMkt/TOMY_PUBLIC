# UX/UI 초씹고수의 4대 지식체계

출처: 사용자 제공 스크립트 (2026-07-14 수집). 화면을 시각/예술 감각이 아니라 심리학·데이터·비즈니스·기술 4개 렌즈로 해체하는 프레임워크.

## 1. 인지심리학·행동경제학 (인간의 '오류'를 지배하는 지식)
"여백을 줘라"가 아니라 "작업기억을 아끼려고 그룹핑해야 한다"고 논리적으로 설득하는 근거.

- **게슈탈트 원칙**: [[reference_ui_ux_core_principles]] 9번에 근접성·유사성·연속성·폐쇄성 4종 통합됨(중복 방지, 여기선 생략)
- **힉의 법칙**: [[reference_toss_ux_psychology_laws]]에 이미 등재(선택지 늘수록 결정시간 증가) — 여기선 "유저에게 선택을 강요하는 최적 타이밍 설계"라는 응용 관점 추가
- **넛지·행동편향** (신규):
  - 손실회피(Loss Aversion) — 혜택을 놓치기 싫게 만드는 미끼 설계
  - 사회적 증거(Social Proof) — 타인의 행동을 보여줘 전환율 상승
  - 초두효과·최신효과(Primacy & Recency) — 리스트 첫/끝 아이템에 핵심 CTA 배치
  - ⚠️ 이 3개는 3번(비즈니스) 항목의 다크패턴 경계선과 항상 같이 검토할 것 — 전환율 올리는 것과 유저 속이는 것의 경계가 얇음

## 2. 데이터 분석·실험 설계 (감정을 '숫자'로 바꾸는 지식) — 전부 신규
"내가 보기엔 이게 더 예쁜데" 같은 주관 논쟁을 데이터로 종식.

- **정량 분석**: SQL/Amplitude/Mixpanel/GA 대시보드 해석 능력. 이탈(Drop-off)·클릭 히트맵·퍼널 병목을 숫자로 짚어내기
- **A/B 테스트 설계**: 안 두 개 만들어 올리는 수준이 아니라, 통계적 유의성 확보 가능한 표본 크기·가설 설계
- **정성 조사**: 사용자 인터뷰(FGI)·사용성테스트(UT) 시 유도질문(Leading Question) 방지, 무의식적 불편함을 끌어내는 모더레이팅

실무 적용: 서비스마스터가 판단 내릴 때 "감"으로 끝내지 말고, "이 판단을 검증하려면 어떤 데이터/실험이 필요한가"를 항상 덧붙일 것.

## 3. 비즈니스 모델·메트릭 (회사의 '돈'을 버는 지식) — 전부 신규
주니어는 "쓰기 편한 화면"만 생각, 초씹고수는 "편하면서 회사 이익도 극대화하는 화면"을 설계.

- **핵심 지표**: LTV(고객생애가치)·CAC(고객획득비용)·Retention(잔존율)·ARPU(유저당평균매출) — UI 변경이 이 지표에 미치는 인과관계를 설명할 수 있어야 함
- **다크패턴 경계선**: 유저를 속이는 나쁜 UI(교묘한 결제 유도 등) vs 브랜드 신뢰를 지키며 매출 올리는 '정직한 넛지'의 한계선을 명확히 구분

실무 적용: 서비스마스터가 UI 판단 줄 때 "이게 어떤 비즈니스 지표에 영향 주는지"까지 같이 답할 것. 고방 BM 관련 판단 시 특히 다크패턴 경계선 체크 필수.

## 4. 프론트엔드 기술·플랫폼 생태계 (개발의 '한계'를 넓히는 지식) — 전부 신규
개발을 모르면 화면 안에서만 노는 반쪽짜리 판단이 됨.

- **프론트 기초**: HTML/CSS, Flexbox/Grid, DOM 렌더링 구조·반응형 원리 이해 — "이 리스트는 CSS Grid로 처리하면 기기별 대응 쉽다" 수준 판단
- **성능·렌더링**: 이미지 용량·컴포넌트 재사용성·스켈레톤 UI가 체감 속도에 미치는 영향을 기획에 반영
- **OS 가이드라인 심화**: iOS/Android 가이드북 표면 지식을 넘어 두 OS의 인터랙션 엔진·제스처 물리감 차이까지 이해하고, 언제 가이드라인을 '파괴'해도 되는지 판단

실무 적용: "개발자 관점에서" 시그널 올 때 이 항목 근거로 Plan 에이전트 판단과 종합.
