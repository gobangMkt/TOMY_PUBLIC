# 토스 "Easy to Answer" 원칙

출처: https://toss.tech/article/insurance-claim-process (2026-07-14 수집)

## 핵심 원칙
사용자가 **대답하기 쉬운 질문**을 던져야 한다. **3초 내에 답이 안 나오면 너무 어려운 질문**이라는 기준.

## 사례: 병원비 돌려받기 기능
- **초기 문제**: "전문가 도움받을까요, 직접 할래요?" 선택지에서 사용자가 고민하며 이탈. 선택 후 어떤 과정이 펼쳐질지 예상 불가.
- **개선**: 모호한 질문 → 명확한 질문
  - Before: "전문가 도움받을래 직접 할래?" (판단을 요구)
  - After: "서류 있어?" (사실 확인만 요구)
- **성과**: 이탈률 50%p 감소 (60%대까지 대폭 감소)

## 추가 개선
- 보험사 선택: 전체 목록 → 가입된 보험사만 노출
- 미가입자용 별도 상담 퍼널 추가

## 실무 적용 원칙
질문형 UI(선택지, 폼 필드)를 만들 때 "이 질문에 사용자가 판단 없이 즉답할 수 있는가"를 체크리스트로 삼을 것. 유용한 기능 추가보다 사용자 관점에서 막힘을 재설계하는 게 전환율에 더 크게 기여함.
