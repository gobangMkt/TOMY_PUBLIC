## 구조 결정
- **아키텍처 경계는 사용자 행동/도메인에서**: 분할 단위는 기술 편의가 아니라 "함께 바뀌고 함께 쓰이면 묶고, 독립적으로 바뀌면 나눈다".
- **분할은 고통이 측정될 때만 (양방향)**: 모놀리식 고통(빌드 30분·PR 엉킴)이 계량될 때만 분할, 그 전엔 모놀리식이 정답(분할비용<현재고통). **역방향도 성립 — 유연성 노려 선제 세분화한 패키지/모듈은 조각이 늘수록 변경 파급·버전 조합 지옥·교차검증이 곱셈으로 커진다. 과분할이 측정되면 통합.** → [[reference_engineering_principles]] YAGNI.
- **공통화는 결합도 스펙트럼**: 공유는 이분법이 아니다(디자인만 공통 → API 공통 → UI+Data 완전통합). 깊게 통합할수록 일관성↑·자율성/장애격리↓, 공통부 장애=전체 장애(blast radius↑) → 롤백·온콜·모니터링이 받쳐줄 때만 깊은 통합. 남이 붙일 공유 모듈은 코드가 도는 것만으론 미완 — 5분 롤백·관측 대시보드·안전 기본값 같은 '신뢰 인프라'까지 딸려야 채택자가 붙는다.
- **횡단 관심사는 중앙에서 주입**: 로깅·모니터링·인증·알림 반복 부가기능은 비즈니스 코드에 흩뿌리지 말고 한 곳(미들웨어·래퍼·데코레이터, Next.js middleware·GAS doGet 래퍼)에서 주입. 같은 부가기능 3곳+ 복붙이면 중앙화 신호. 인증은 진입 최앞단 1회 검증→통과된 신원을 일관 컨텍스트로 하류에. **⚑ "성공하면 부수효과"(외부 액션 성공 시 로컬 DB 미러 갱신 등)는 호출부가 아니라 그 액션을 감싸는 최하위 함수 안에 둬라** — 호출부에 두면 새 호출부가 생길 때마다 손으로 복붙해야 하고, 손으로 지켜야 하는 규약은 반드시 무너진다(메일허브 2026-08-04: 4곳 복제 중 1곳이 순서까지 틀려 Gmail 실패 시 DB가 영구 불일치). 가드레일>게이트의 정합성 버전.
- **배선 은닉(퍼사드)**: 소비자(다른 화면·다른 팀·미래의 나)가 여러 프로바이더·모듈 버전·초기화 순서를 직접 배선해야 하면 그게 결합이자 인지부하다 → 진입점 하나(퍼사드/래퍼)로 배선을 숨기고 소비자는 '의도'만 넘기게(부가 인프라는 자동 주입=안전한 기본값). (소비자 하나뿐이면 프레임워크화는 YAGNI)
- **확장점 역전 (레지스트리/플러그인)**: 새 변형·소스가 늘 때마다 코어를 직접 고치면 N×M 결합이 폭발 → 코어는 닫고 안정적 확장 인터페이스(레지스트리 등록·config 1항목·훅)만 열어 변형을 '꽂게'(개방-폐쇄). CS도움앱 inbox `sources.js` '1항목 추가'가 소형 구현. (2~3개 변형까진 하드코딩이 쌈, YAGNI)
- **느린 피드백 루프 = 구조 개선 트리거**: 저장→화면 반영, 빌드/로컬 기동이 체감 느려지면 그 자체가 리팩터 신호(우선순위 올려라).
  - **⚑⚑ 지켜지지 않는 규칙은 의지 문제가 아니라 마찰 문제다 — 규칙을 다시 외치지 말고 마찰을 없애라** (2026-08-11 고방어드민 실증). "운영은 prod로 띄운다"는 결정이 7/31에 이미 있었는데 8/11에도 dev가 떠 있었다. 원인은 기동 배치가 **매 실행 풀빌드(수십 초)** 를 돌린다는 것 — 사람은 그 대기를 피해 즉시 뜨는 `npm run dev`로 우회하고, 그 상태가 며칠 유지된다. 고친 방식은 규칙 강화가 아니라 **대기 제거**였다: 소스 지문(파일 크기+수정시각 해시)이 그대로면 빌드를 건너뛰고 즉시 기동(실측 4.4초), 바뀌면 반드시 빌드(그래서 "옛 빌드가 서빙된다"는 prod 모드의 원래 단점도 같이 사라진다). **올바른 경로가 가장 편한 경로가 되면 규칙은 저절로 지켜진다** — 가드레일>게이트의 마찰 버전. ⚠️ 이때 스탬프는 **빌드 성공 후에** 찍고, 빌드 도구가 스스로 고치는 파일(Next는 `tsconfig.json`·`next-env.d.ts`)을 감안해야 한다 — 빌드 전 지문을 찍으면 매번 불일치가 나 **스킵이 영영 안 걸린다**(실측으로 발견).

## 보안 · 권한
(공격면 인지·마인드셋은 [[reference_engineering_principles]] DevSecOps, HMAC·nonce·입력 스키마 검증은 [[reference_integration_data]] 인바운드 경계. 여기는 최소권한·회수·격리 정본.)
- **가드레일 > 게이트**: 반복되는 위험한 실수는 사람 리뷰(게이트)로 막지 말고 애초에 못 하게 기본 구조로 차단(가드레일). 같은 실수 2회+·비용 크면 기본값·lint·타입·부팅검사로 강제. **'스테이징이 실운영 DB를 가리키는' 류 치명 설정은 설정 파일 단위테스트/타입으로 배포 전 assert(policy-as-test), 풀스캔·상한 없는 조회·페이지네이션 없는 목록은 앱/프록시에서 구조 차단(인덱스/파티션키 필수·결과 상한 = bounded access, Supabase limit·RLS·GAS 범위).** → [[reference_engineering_principles]] "시스템으로 강제".
- **안전한 기본값 (Pit of Success)**: 아무것도 안 하면 안전한 게 default, 위험한 선택에만 의식적 노력. **위험한 원본 툴(배포·크론·인프라 설정)은 그대로 노출 말고 안전 기본값 품은 좁고 발견가능한(IDE 자동완성) 헬퍼/빌더로 감싸라. 반납·회수·정리 같은 '옳은 행동'은 사용자가 이미 있는 자리(메신저)에 원클릭으로(내부 툴도 DX가 채택률). 비가역·위험 행동은 오히려 확인 마찰을 일부러.** (거의 보편 / 1회성 스크립트엔 과함)
- **Fail Fast at Startup**: 설정 오류·필수 env 누락은 런타임 중이 아니라 부팅/빌드 시점 크래시로. 조용히 기본값 먹지 말 것. → [[reference_engineering_principles]] 시크릿 런타임 주입과 짝. (필수 설정 없는 순수 로컬 유틸이면 과함)
- **자격증명 컨텍스트 잠금 (Defense in Depth)**: 키/토큰 하나에 전권 주지 말고 최소권한 스코프+허용 IP/대역+만료를 자격증명 자체에 박아 새어도 정해진 컨텍스트 밖에선 안 먹게 2중 잠금. 발송/결제 키는 서버에서만·IP 화이트리스트, Supabase는 RLS+publishable/service 키 분리. (권한 큰 키 발급 전 항상)
- **권한 라이프사이클은 회수까지 설계**: 계정·API키·공유링크·배포URL은 부여 시점에 만료/회수 트리거를 함께. **정적·영구 키를 코드·env에 박지 말고 짧은 수명 임시 토큰을 동적 발급(유출돼도 만료로 자동 무력화 — GitHub Actions OIDC·Supabase 짧은 JWT). 권한은 IP·개별 규칙 아닌 '직무/역할 속성'에 바인딩해 역할이 바뀌면(이동·퇴사) 코드 수정 0으로 자동 회수(Supabase RLS role).** (1인/단일역할이면 만료일+정기 점검으로 충분)
- **인증/인가는 지속 상태 (Continuous Verification)**: 한 번 통과했다고 세션 내내 신뢰하지 마라 — 도중 계정 비활성화·권한변경이 발생. 장수명 세션·고위험 액션(결제·삭제·관리자) 앞에선 현재 상태를 재검증, 나빠지면 즉시 끊어라. (단발·저위험 읽기는 JWT 만료까지 신뢰로 충분)
- **desired vs actual 드리프트 감사**: 같은 상태가 두 곳(정본 vs 실배포)에 있으면 반드시 어긋난다 → 주기 대조로 불일치 탐지. **IP·CORS·권한 예외는 '이번만'이 쌓여 부패하니 만료(TTL)/주기 감사로 자동 축소.** (소규모=탐지+알림 / 대규모=자동교정, 자동교정 먼저 만들지 말 것)

## 성능 · 캐시
- **DB 커넥션 풀링 필수, 특히 서버리스**: 매 요청 맺고 끊으면 병목·고갈. 서버리스(Vercel)+관리형 DB는 커넥션 폭발 함정 → 반드시 pooler(Supabase pooler/PgBouncer). **커넥션 풀 3대 체크: 예열(콜드스타트)·유휴 정리(DB가 먼저 끊어 나는 에러 방지)·누수 감지(반납 안 된 커넥션).**
- **실행 모델 불일치를 의심하라**: 동기 코드를 비동기 서버에 얹으면 매 요청 새 스레드→새 커넥션으로 악화. 성능 이상하면 "런타임(sync/async·서버리스/상시)과 라이브러리 전제가 맞나"부터.
- **병목은 추측 말고 계측·부하테스트로**: "빨라졌다"를 측정 없이 주장 금지, 개선은 전후 비교. **지연이 대기(I/O·락·sleep)로 지배되면 CPU 프로파일러는 놓치니 wall-clock으로, 프로파일러는 프로세스 t=0에 붙여 초기화까지 잡아라.** (순수 연산 병목은 CPU 프로파일링)
  - **⚑ 성능 판정은 프로덕션 빌드 + 실데이터 볼륨에서만** (2026-08-11 메일허브 실증). dev 런타임은 비최적화 런타임(React dev 빌드)+HMR/Fast Refresh 개입으로 신호가 3~10배 뭉개진다 — 같은 변경을 dev에선 "88~296ms 남음"으로, prod에선 "0ms"로 읽었다. **before/after는 반드시 같은 빌드 모드에서** — 개선 후만 prod로 재고 기준치는 dev 수치를 쓰면 비교가 통째로 거짓이 된다(원본 코드를 다시 빌드해서라도 같은 조건으로 잡아라).
  - **⚑ 측정 창에 배경 작업이 섞였는지부터 확인하라**: 유휴 대조군(클릭 없이 같은 길이로 재기)과 그 창에 뜬 네트워크 요청을 함께 기록해야 "전환 비용"과 "때마침 도착한 폴링·동기화"를 가른다. 대조군이 0이 아니면 그 표본은 버린다.
  - **⚑ 레이아웃 회귀는 스크린샷이 아니라 수치로**: `scrollWidth > clientWidth`를 요소 단위로 훑어라. 눈으로는 "괜찮아 보이는" 32px 오버플로가 잡힌다(같은 세션에서 실제로 래퍼 하나 잘못 넣어 1032→2488px 오버플로를 스스로 냈고, 스크린샷으론 못 잡고 계측으로 잡았다).
- **부하 대응은 값싼 레버부터**: ①스케줄 분산(몰릴 이유 없는 배치는 시간대만 옮겨) → ②요청 묶기(배칭·IN절 벌크·배치INSERT·루프전 캐싱으로 호출수/개당고정비↓, N+1 제거) → ③레이트리밋 → ④병렬 동시성을 가장 좁은 병목 자원(DB 커넥션·외부 한도)에. **비싼 조회(DB·외부API) 앞엔 값싼 게이트(인메모리 셋·존재 인덱스)로 '확실히 없음'을 먼저 걸러 헛수고 I/O 제거.** (최후에야 인프라 증설·재작성 / 반응성 운영은 오늘 터진 것·최고 임팩트부터 그리디하게)
- **쿼리 스캔 프루닝**: '인덱스를 걸었다'와 '데이터가 그 인덱스에 맞게 물리 배치돼 있다'는 별개 — 자주 함께 조회하는 컬럼 기준 물리 정렬/클러스터링·복합인덱스 컬럼순서로 불필요 블록을 통째로 스킵. 인덱스 있는데 특정 쿼리가 느리면 로컬리티부터. (정렬 배치는 쓰기비용↑라 읽기 압도 우위 테이블만·전후 실측 필수 / BRIN·파티셔닝은 BQ 대용량 한정, Supabase 소볼륨엔 과함)
- **핫패스 최소화 — 이연 + materialize**: 사용자가 기다리는 읽기/쓰기 핫패스에서 무거운 계산 금지. 쓰기=append 후 즉시 ack하고 집계는 백그라운드/배치로, 읽기=미리 계산해 적재한 값 조회만(조회 부하 실측 후 필요하면 조회 전용 뷰=CQRS). → 쓰기 append는 [[reference_integration_data]] 금전 append-only. (계산 값싸거나 staleness 불가면 온더플라이)
- **캐시·프리로드는 재사용율 > 무효화율일 때만**: 프리컴퓨트·프리페치·예열은 재사용 주기가 무효화 주기(배포·데이터 변경)보다 빠를 때만 히트율이 유지돼 이득 → 도입 전 무효화 주기부터 재고(신청허브 캐시버스팅 이력). 투기적 작업은 3게이트로 좁혀라: ①변경감지(버전/ETag 같으면 스킵) ②수혜 가능성(최근 활성 대상만) ③자원 안전(저부하·무료망). (배포·데이터가 주~월 단위로 느리면 적극 / 배포 잦거나 개인화·실시간이면 보류)
- **must-be-fresh 데이터는 캐시 금지**: 버전 해시 박힌 정적 JS/CSS/이미지는 적극 캐시, 응답에 개인화·실시간·민감 데이터(잔액·주문상태·권한)가 섞이면 캐싱 금지(해지한 카드가 옛 화면에 뜨는 오노출). 정적 셸=캐시, 동적 데이터=매번 fetch. 판정 기준은 '틀려도 되나'가 아니라 '누가 봐도 같은가'.
- **할당 ≠ 사용 (자원 낭비 2축 계측)**: '가동 중'(liveness)은 실사용 보장 X → 점유(allocated)와 실사용(actually used)을 별도로 계측해야 유휴 DB 커넥션·놀고 있는 크론/람다·미사용 SaaS 시트가 잡힌다. 돈 새는 자원은 '돌고 있나' 아닌 '제대로 쓰이나'로.
- **일관성은 연산별 다이얼**: on/off가 아니라 연산마다. 쓰기는 강하게(확정 저장 확인 후 성공 판정), 단순 조회는 약하게(약간 stale 허용). **단 읽은 값으로 즉시 쓰기 판단(잔액·재고·중복결제 체크)이면 그 읽기는 강한 일관성으로.**

## 워크플로 · 병렬
- **조합 폭발은 국소 불변식의 합성으로**: 상태·단계가 계층적으로 중첩·증식하는 워크플로/오케스트레이션(트랜잭션 N개×성공/실패/불명)은 전역 케이스 매트릭스로 불가 → '전체 상태 = 국소 규칙의 합성', 각 단위 상태를 오직 직속 하위 상태만으로 결정(1레벨 규칙). [[reference_code_craft]] 합성 우선의 워크플로 적용판.
- **준비상태 관측으로 디커플링**: 작업 간 의존을 'A 끝나면 B' 하드와이어링으로 묶지 말고 B가 자기 입력(데이터·파일·상태) 준비를 스스로 관측해 진행 → 한 작업 실패가 체인 전체로 전이되는 blast radius를 끊는다. (크론·GAS·다단계 파이프라인에서 하위 실패가 핵심 경로를 멈추면 안 될 때 / 선형 2~3스텝은 명시 순서가 명확)
- **벌크헤드 장애 격리**: 결제·인증 치명 경로는 실패·폭주 가능성 있는 비신뢰/부가 코드(외부 플러그인·서드파티·무거운 잡)와 격리 경계로 분리(별 서버리스 함수·큐 워커·격리 try/catch)해 후자가 죽어도 전자는 산다. (부가 코드 신뢰 가능+경로 비치명이면 오버킬)
- **병렬 처리는 결정적 키 분할 (shared-nothing)**: 여러 워커가 같은 데이터셋을 동시 처리하면 누락·중복 → 락 경합 대신 ID 모듈러(%N)·해시 범위로 파티션을 갈라 각 워커가 겹치지 않는 몫만 전담. 오케스트레이터+워커N(claude -p 병렬)·병렬 배치 설계 시.
- **폴링 → 이벤트 기반**: 주기 조회는 주기만큼 지연+매 주기 조회부하. '몇 분 늦어도 되나?' Yes면 폴링/스케줄이 최저비용(값싼 레버)이니 유지, No(초 단위 요구)면 웹훅·DB 트리거·스트림으로 전환. (GAS 트리거 vs 웹훅 선택에 직결)

## 배포 · 기동
- **점진적 롤아웃 (카나리/피처플래그)**: 롤백 비용 큰 변경(결제·인증·대규모 UI 개편)은 전량 배포 말고 일부 먼저 → 지표 보고 확대(소규모는 쿠키/유저ID% 분기·피처플래그). **정확성 미션크리티컬 로직(정산·요금·문구/SQL 생성) 재작성은 신·구 엔진을 실데이터로 동시 실행해 출력 1:1 대조, 일치분만 전환·불일치는 구 시스템 폴백 후 격리 분석(shadow run). 성공/건강 지표는 코호트(디바이스·가맹점)별로 쪼개 배포 직후 감시(한 세그먼트 0건이어도 평균은 멀쩡해 보임).**
- **콜드스타트/구동은 복리 지표**: 기동 시간은 dev 피드백 루프 × 장애복구(스케일아웃) 양쪽에 곱해지는 복리 비용 → 서버리스 콜드스타트·claude -p 워커 재기동·GAS 재실행처럼 재기동 잦은 워크로드는 startup을 명시 지표로. 공통·shared 모듈이 부팅 때 모든 실행모드 클라이언트를 싹 로딩하면 각 역할이 남의 초기화 비용까지 내니, 역할(웹/배치/워커)별 초기화를 조건부 격리(무거운 배럴 import 경계). (상시 롱러닝 단일 프로세스라 재기동 드물면 우선순위 낮춤)
- **설정·인프라도 코드다 (Config as Code)**: env·vercel.json·appsscript.json·크론·GAS 트리거를 콘솔 수기클릭/복붙으로 관리하면 정합성이 깨져 곧 장애 → 코드로 선언해 버전관리·리뷰·CI 강제, Git을 단일 진실원으로. 환경/앱마다 전체 복사 말고 base(공통)→환경 override→앱 override로 델타만 병합. 신규 소스는 코드수정 아닌 설정추가로. (단일 환경·항목 소수면 파일 분리로 충분 YAGNI, 커스텀 IaC 플랫폼 자체 개발은 바퀴재발명) → 빌드 산출물 계층화(vendor/앱코드 레이어 분리)는 번들러·빌드캐시 기본값에 위임, 손으로 가르지 말 것.
- **프레임워크 코어 우회는 최후 수단**: 표준으로 안 되면 설정·공식 확장 먼저 → 정 안 되면 우회, 단 업그레이드 때 깨질 각오 + 테스트 동반.
- **⚑ 검증이 사용자를 끊지 않게 한다** (2026-08-21 찐정책). 사용자가 *"찾기 안 되는데 지금?"* 이라 신고해 실측하니 전 라우트 200·콘솔 에러 0이었다 — 그 시각 내가 **사용자가 쓰는 그 포트에서** `.next` 삭제 후 재빌드 중이라 10~20초씩 서버가 죽어 있었다. **검증하겠다고 사용자 화면을 끈 것**이고 사용자는 그걸 제품 고장으로 읽었다. 빌드·재기동은 **사용자가 보는 포트가 아닌 곳**에서 돌리고, 불가피하면 **"지금 재기동 중"을 먼저 알린다.**
