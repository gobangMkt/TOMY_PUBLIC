## RAG (사실 기반)
- **사실 기반 답변엔 RAG**: LLM이 규정·정책·가격처럼 정확성이 중요한 걸 답하면 모델 파라미터 지식에 맡기지 말고 신뢰문서를 검색해 근거로 주입(환각·법적리스크 차단). (답이 출처·최신성을 요구하면 RAG, 범용 창작이면 불필요 YAGNI)
- **RAG 품질은 전처리(청킹)에서 갈린다**: 원문 통째 임베딩 금지. 표·이미지·중첩구조는 평문 나열로 풀어 청크 단위 의미를 보존. 검색 실패의 1차 원인은 모델이 아니라 인덱싱된 데이터. (표·이미지·중첩 없는 평문 위주면 통짜 임베딩도 무방 — 청킹 투자는 구조화 문서일 때)

## 프롬프트 · 정확도
- **엣지케이스 퓨샷**: 퓨샷 예제는 '잘 되는 예'가 아니라 모델이 가장 헷갈리는 엣지케이스를 골라 넣어라(엣지 주입으로 정확도↑). 출력 정확도가 안 나오면 예제 '개수'보다 '헷갈리는 경계'를 채워라. (결과를 규칙으로 검증 가능하면 굳이 늘릴 필요 없음)
- **어려운 분류를 페어와이즈 이진 판별로 재정의**: 레이블이 부족하거나 난이도 높은 분류(레이블 부족·클래스 경계 모호, 예: 대량 상품 그룹핑)를 '둘이 같나 T/F'처럼 데이터 요건 적은 1:1 이진 판별로 재정의하면 소량 레이블·프롬프트로도 작동. (충분한 레이블 있으면 직접 분류가 단순 — 페어와이즈 조합비용 감수 금지)

## 비용 · 모델 전략
- **지식 증류·부트스트래핑 비용 사이클**: 레이블 0에서도 비싼 대형 LLM(Opus·GPT)으로 즉시 자동화를 시동해 골든 예시를 대량 생성 → 정합성 높은 출력을 레이블로 축적한 뒤 그 페어로 값싼 소형모델·few-shot·캐시를 온라인 서빙에 태워 런타임 토큰·호출단가를 급감. 에스컬레이션은 프롬프트→RAG→증류 순. (우리는 대부분 API 소비자라 실효는 토큰비·호출단가↓·캐시 — 파인튜닝·자체 GPU 서빙은 반복 호출량이 아주 클 때 최후만, 저볼륨이면 대형 API 유지가 더 쌈) → [[reference_engineering_principles]] 적정기술의 LLM판.

## 품질 평가 · 개선 루프
- **LLM-as-a-Judge**: LLM 출력 품질/표준 준수를 사람이 일일이 대조하는 병목 대신, 검증된 채점 프롬프트(감점기준+1~5점)로 LLM이 LLM 출력을 자동 채점하고 결과를 개발자가 보는 곳(슬랙 리더보드)에 상시 노출해 회귀·A/B를 닫힌 루프로. (결과를 규칙(정규식·스키마)으로 검증 가능하거나, judge 신뢰 안 서는 고위험이면 사람 최종검수 유지)
- **AI 교정 피드백을 지식으로 재투입**: 담당자가 고친 답변을 버리지 말고 다시 인덱싱 → 다음 답변에 반영. 1회성 답변을 지속개선 루프로(서비스마스터 실전 사례 증류와 같은 결). (답변량·재사용 빈도가 낮으면 재인덱싱은 오버 — 반복 질의가 쌓이는 도메인에만)
- **프롬프트·평가결과 Git 버전관리**: 프롬프트·모델 파라미터·평가결과를 DB/UI에 흩뿌리지 말고 Git으로 버전관리해 재현·롤백·A/B 추적(일반 config 형상관리와 별개, 여기선 프롬프트 자산 한정). (거의 안 바뀌는 단일 고정 프롬프트면 과함)

## 파이프라인 · HITL
- **LLM 체이닝 분해 + 신뢰도 기반 HITL 라우팅**: 한 프롬프트에 다 시키지 말고 초안→교정→셀프검수→재수정처럼 태스크별로 쪼개 체이닝하고, 결과는 신뢰도로 라우팅 — 최고점만 즉시 자동 반영, 낮은 점수는 사람이 모니터링 툴로 교정(Human-in-the-Loop). (정확도가 중요한 작업에 / 오류 허용도 높은 초안·창작이면 체인·게이트 과함 YAGNI)
- **AI 파이프라인은 전문가 암묵지 관찰에서**: AI로 대체할 업무는 명세서가 아니라 숙련자의 실제 동작·시선을 옆에서 관찰해 역설계하라(숙련자가 3배 빠른 이유가 '상세 이미지에서 제조사·용량·묶음수량을 본능적으로 스캔'하는 암묵지였고 그걸 OCR+LLM 파이프라인으로 모사). [[reference_engineering_principles]] 현장리서치의 AI 적용판. (명세로 이미 정형화됐고 암묵지 없는 업무면 관찰 불필요)

## 정합성 가드
- **확률판단 전이연결은 오류 전파 → 정합성 가드**: 페어와이즈/LLM 판단을 전이적으로 이어붙여 그룹을 만들면 단 1건 오판이 그룹 전체를 오염시킨다(도미노). LLM·확률모델 출력을 조합·연쇄할 땐 할루시네이션이 누적되므로, 그룹 확정 후 비교 안 해본 노드쌍을 무작위 교차검증(불변식·랜덤 크로스체크)해 불량 그룹을 즉시 해체하는 결정론적 가드를 붙여라. → [[reference_architecture_ops]] 결정론적 가드와 같은 결. (독립 판단이면 불필요)
