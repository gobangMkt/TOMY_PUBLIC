# 구글 Search Console 페이지 색인 생성 보고서: 사유별 정의와 조치

> 마케팅팀장 지식. Search Console 색인 보고서의 사유를 해석하고 조치를 정할 때 쓴다. 출처: 구글 Search Console 도움말(URL 하단). 회사 실측 데이터는 담지 않는다.

기준: 2026-10-17 시점 한국어판(hl=ko)과 영어판(hl=en). 분류 열은 공식 문서에 명시된 표현이 있을 때만 "기다림 / 글 수정 / 기술 조치"로 적고, 근거가 없으면 "공식 분류 없음"으로 둔다. 문서가 정한 분류가 아니라 문서 문구에서 읽어낸 것은 "해석"이라 표시한다.

## 0. 보고서 뼈대

- 상태는 두 개: 색인 생성되지 않음(Not indexed), 색인 생성됨(Indexed). 색인됨 그래프 아래에서 예시 URL을 최대 1,000개까지 볼 수 있다. (7440203)
- 표의 "출처" 값이 웹사이트인 문제만 사이트 쪽에서 고칠 수 있다. 구글 쪽 출처 문제는 손쓸 수 없으니 웹사이트 출처부터 처리한다. (7440203)
- 사유 목록은 오류, 기타(제외), 경고 세 덩어리다. 아래 표도 같은 순서.
- 사이트맵 필터(제출된 모든 페이지 / 제출되지 않은 페이지만 / 특정 사이트맵)로 범위를 좁혀 볼 수 있다. 다른 경로로 발견됐어도 사이트맵에 넣었으면 제출된 페이지로 친다. (7440203)

## 1. 오류 계열 (색인 안 됨, 기술 조치 중심)

| 한국어 | 영어 | 뜻 | 구글 권장 조치 | 분류 |
|---|---|---|---|---|
| 서버 오류(5xx) | Server error (5xx) | 서버가 500번대 응답 | 크롤링 통계 보고서로 호스트 상태 확인, 과부하 줄이기, 방화벽/DoS 방지가 Googlebot을 막는지 점검 | 기술 조치 |
| 리디렉션 오류 | Redirect error | 체인이 너무 길거나 순환, URL 길이 초과, 잘못되거나 빈 URL 포함 | 리디렉션 구조 정리 | 기술 조치 |
| robots.txt에 의해 차단됨 | Blocked by robots.txt | robots.txt 규칙이 크롤링을 막음 | 의도한 차단인지 확인. 색인을 막을 목적이면 robots.txt 차단을 풀고 noindex를 쓴다 | 기술 조치 |
| noindex로 표시됨 | Marked noindex | 태그나 HTTP 헤더에 noindex | 색인을 원하면 noindex 제거 | 기술 조치 |
| 소프트 404 | Soft 404 | 없는 페이지인데 404 코드 없이 "없음" 메시지만 보이고 200 응답 | 진짜 404를 반환하거나 페이지에 실제 콘텐츠를 채운다 | 기술 조치 또는 글 수정(둘 다 문서가 제시) |
| 승인 필요(401) | Blocked due to unauthorized request (401) | 인증을 요구함 | 인증 제거 또는 Googlebot 허용 | 기술 조치 |
| 찾을 수 없음(404) | Not found (404) | 페이지가 없음 | 삭제한 페이지면 문제 아님. 사이트 내 링크나 사이트맵에 남은 URL만 우선 수정. 이동했으면 301 | 기술 조치(삭제 의도면 조치 불필요) |
| 액세스 금지(403) | Blocked due to access forbidden (403) | 로그인 없는 Googlebot에 403 반환 | Googlebot과 비로그인 사용자 접근 허용 | 기술 조치 |
| 기타 4xx 문제로 차단됨 | Blocked due to other 4xx issue | 위 항목에 없는 4xx | URL 검사 도구로 디버깅 | 기술 조치 |

## 2. 기타 계열 (제외 사유, 오류가 아닐 수 있음)

| 한국어 | 영어 | 뜻 | 구글 권장 조치 | 분류 |
|---|---|---|---|---|
| 크롤링됨 - 현재 색인이 생성되지 않음 | Crawled - currently not indexed | 구글이 가져갔지만 색인에 넣지 않음. 나중에 색인될 수 있음 | 재제출할 필요 없음 | 기다림. 이유 설명은 문서에 없음 |
| 발견됨 - 현재 색인이 생성되지 않음 | Discovered - currently not indexed | URL은 알지만 아직 크롤링 전. 사이트 과부하를 피하려고 일정을 미룬 경우 | 별도 조치 없음 | 기다림 |
| 대체 페이지(적절한 표준 태그 포함) | Alternate page with proper canonical tag | 올바른 표준 페이지를 가리키는 대체 URL | 조치 불필요 | 조치 불필요 |
| 사용자가 선택한 표준 페이지가 없는 중복 페이지 | Duplicate without user-selected canonical | 다른 페이지와 중복이고 표준을 선언하지 않아 구글이 다른 페이지를 골랐다 | 보통 정상. 필요하면 표준 URL을 명시 | 정상 동작. 판단은 의도 따라 |
| 중복, 구글이 선택한 표준이 사용자와 다름 | Duplicate, Google chose different canonical than user | 선언한 표준과 구글이 고른 표준이 다름 | URL 검사로 두 선택을 비교하고 페이지를 대조 | 공식 분류 없음 |
| 리디렉션이 있는 페이지 | Page with redirect | 리디렉트되는 URL이라 색인 제외. 대상 URL은 색인될 수 있음 | 대상 URL 상태를 확인 | 조치 불필요(대상이 문제일 때만) |

규칙 해석 주의: "중복 제출된 URL이 표준으로 선택되지 않음", "크롤링 이상" 두 항목은 확인한 한국어판 본문에 없다(두 번째 파일 4절). 표에 못 적는다.

## 3. 규칙: 증상 → 판정 → 할 일

1. 크롤링됨/발견됨 - 색인 안 됨 → 문서는 오류로 보지 않고 재제출 불필요라 한다 → 기다리며 URL 검사로 진행 확인. 문서가 기다림 기간을 수치로 주지 않는다(새 페이지는 보통 약 1주 이상, 일부 사이트는 수 주). (7440203 en, 6065812)
2. 크롤링됨 - 색인 안 됨이 오래 간다 → 문서에 원인 목록이 없다. 해석: 콘텐츠 품질·중복 쪽을 의심하는 것은 이 문서 밖 판단이다. 확정 사유로 쓰지 않는다.
3. 발견됨 - 색인 안 됨 → 해석: 사이트 과부하 회피라는 문서 설명상 서버 응답이 느리면 5xx 점검이 먼저. 크롤링 통계 보고서 확인(호스트 상태 도움말 9679690).
4. noindex 또는 robots.txt 차단 → 의도했는지 먼저 확인 → 색인을 원하면 noindex 제거, robots.txt 차단 해제. 색인을 막을 땐 robots.txt가 아니라 noindex(robots.txt로 막히면 구글이 noindex를 못 읽는다). (7440203, 9012289)
5. 소프트 404 → 진짜 없는 페이지면 404/410 응답, 있어야 할 페이지면 콘텐츠를 채움. (7440203, 181708)
6. 404 → 지운 글이면 방치해도 되고, 내부 링크·사이트맵에 남았으면 제거, 이동했으면 301. 404 목록은 지난 1개월 안에 404를 만난 URL만 보여준다. (7440203 en, 2445990)
7. 중복·표준 계열 → 정상 동작일 수 있다. 구글이 고른 표준이 의도와 다르면 URL 검사의 "Google에서 선택한 표준 URL"과 선언 표준을 비교하고 표준 URL을 명시하거나 콘텐츠를 차별화. (7440203, 12642436)
8. 대체 페이지 / 리디렉션이 있는 페이지 → 올바르게 설정된 결과, 조치 없음. 대상 URL 상태만 확인.
9. 5xx/401/403/기타 4xx → 사이트 접근 문제. 웹사이트 출처이므로 즉시 기술 조치.

## 4. 수정 후 확인(검증) 절차

- 해당 문제의 모든 인스턴스를 먼저 고친다. 하나라도 남으면 확인이 중단된다. (7440203)
- 문제 세부정보에서 "수정 결과 확인" 클릭. 성공·실패 알림 전에는 다시 누르지 않는다. 사이트맵 필터를 켠 채 누르면 그 사이트맵 URL만 대상.
- 소요: 보통 최대 2주, 더 걸릴 수 있다. 구글은 이메일로 성공·실패를 알린다.
- 실패하면 세부정보에서 실패 URL을 고친 뒤 "새로운 확인 시작". 대기 중 또는 실패 URL만 재점검한다.
- 동작: 먼저 샘플 페이지를 검사해 오류가 보이면 바로 종료. 알려진 영향 URL만 재크롤링 큐에 들어가고 사이트 전체를 다시 돌지 않는다.
- 수정으로 인정되는 경우: 문제 없이 크롤링됨, 또는 페이지가 접근 불가(삭제, noindex, 로그인 보호)가 됨.
- 요청 없이도 정기 크롤링에서 전부 해결을 감지하면 수를 0으로 갱신한다(상태 N/A).

| 문제 단위 상태 | 뜻 |
|---|---|
| 시작되지 않음 Not started | 확인을 요청한 적 없음 |
| 시작됨 Started | 확인 진행 중, 남은 인스턴스 아직 못 찾음 |
| 문제 없음 Looking good | 지금까지 검사한 인스턴스는 해결됨 |
| 통과 Passed | 알려진 인스턴스 전부 사라지거나 접근 불가, 확인 요청한 경우 |
| 해당 사항 없음 N/A | 요청 없이 구글이 해결을 감지 |
| 실패 Failed | 확인 뒤에도 문제 페이지가 충분히 남음 |

| URL 단위 상태 | 뜻 |
|---|---|
| 대기 중 Pending | 점검 대기. 마지막 크롤링 때 문제가 있었음 |
| 통과 Passed | 문제가 사라짐(확인 요청 뒤에만 가능) |
| 실패 Failed | 여전히 문제(확인 요청 뒤에만 가능) |
| 기타 Other | URL에 접근 못 했거나 항목을 못 찾음. 통과와 같게 취급, 오류 아님 |

- 문제 기록 유지: 마지막 인스턴스가 해결된 뒤 90일까지 표에 남는다. 해결 후 15일 안에 재발하면 같은 문제, 91일째 재발하면 새 문제로 기록. (7440203 ko)

## 5. 규칙 요약: 분류별 첫 행동

- 기다림: 크롤링됨/발견됨 - 색인 안 됨. 검증 버튼 대상 아님으로 읽는 것이 안전(해석).
- 글 수정: 소프트 404(콘텐츠 보강 쪽 선택지). 그 외는 문서가 글 수정으로 단정한 사유가 없다.
- 기술 조치: 5xx, 리디렉션 오류, robots.txt, noindex, 401, 403, 기타 4xx, 404 이동분.
- 조치 불필요: 대체 페이지, 리디렉션이 있는 페이지, 삭제 의도의 404.
- 이 파일 밖: 경고 계열, 색인됨, URL 검사, 색인 생성 요청 한도는 `google-index-report-indexed-and-tools.md` 참고.
