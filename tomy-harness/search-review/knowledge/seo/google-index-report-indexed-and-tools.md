# 구글 색인 보고서: 색인됨, 경고, URL 검사, 색인 생성 요청, 사이트맵

> 마케팅팀장 지식. Search Console 색인 보고서의 사유를 해석하고 조치를 정할 때 쓴다. 출처: 구글 Search Console 도움말(URL 하단). 회사 실측 데이터는 담지 않는다.

색인 안 됨 계열 사유는 `google-index-report-reasons.md`. 이 파일은 나머지.

## 1. 색인 생성됨과 경고

| 한국어 | 영어 | 뜻 | 구글 권장 조치 | 분류 |
|---|---|---|---|---|
| 페이지 색인이 생성됨 | Page is indexed | 색인에 포함됨. 구조화된 데이터 등 다른 문제는 URL 검사에서 확인 | 필요 시 URL 검사로 개선 항목 확인 | 조치 불필요 |
| robots.txt에 의해 차단되었으나 색인이 생성됨 | Indexed, though blocked by robots.txt | 다른 페이지의 링크 정보로 색인됨 | 색인을 원하면 차단 해제, 빼고 싶으면 robots.txt가 아닌 noindex | 기술 조치 |
| 콘텐츠 없이 색인이 생성됨 | Page indexed without content | 색인은 됐지만 구글이 내용을 읽지 못함(예: 클로킹) | 페이지를 URL 검사로 직접 점검 | 기술 조치 |

(7440203). 색인됐다고 검색 노출이 보장되지는 않는다. (9012289)

## 2. URL 검사 도구 상태

| 상태 | 뜻 |
|---|---|
| URL이 Google에 등록되어 있음 | 색인됨, 검색결과에 표시될 수 있음. 표시 보장은 아님 |
| 등록되어 있지만 문제가 있음 | 색인됨, AMP나 구조화된 데이터 오류로 개선 기능이 빠질 수 있음 |
| URL이 Google에 등록되어 있지 않음 | 검색결과에 못 나옴. 색인 생성 가능 여부 섹션의 원인 확인 |
| URL이 대체 버전임 | AMP 같은 대체 페이지. 구글이 고른 표준 URL이 예상과 같은지 확인 |

실시간 테스트 결과: 등록할 수 있음 / 등록할 수 있지만 문제가 있음 / 이용할 수 없음. 사이트 전체 문제(DNS 오류, 서버 연결 오류, 잘못된 SSL 인증서, robots.txt를 찾을 수 없음, 호스트 로드 초과)로 이용 불가가 될 수 있다. (9012289)

## 3. 규칙: 증상 → 판정 → 할 일

1. 일반 URL 검사 결과 → 마지막으로 색인된 버전을 보여주며 실시간이 아니다 → 방금 고친 페이지는 실시간 테스트로 확인. (9012289)
2. 실시간 테스트 통과 → 색인 가능하다는 뜻일 뿐 보장 아님. 품질 가이드라인, 직접 조치, 콘텐츠 삭제, 임시 차단, 사이트맵 포함 여부는 이 테스트가 보지 않는다. (9012289)
3. robots.txt로 막힌 페이지 → URL 검사의 "색인 생성 허용 여부"가 항상 예로 나온다. 구글이 noindex를 읽지 못하기 때문. noindex가 걸렸는지는 이 값으로 판단 불가. (9012289)
4. 리디렉션 URL을 검사 → 검색결과에는 검사한 URL이 나올 수 있다. 리디렉션 대상의 색인 결과는 따로 검사. (9012289)
5. 구글 선택 표준 URL 값 → 구글 색인보다 몇 시간 늦을 수 있다. (9012289)
6. 동영상 → 실시간 테스트에서 감지만 되고 동영상 색인 상태는 보고되지 않는다. (9012289)

## 4. 확인한 한국어판에 없던 사유

- 크롤링 이상(Crawl anomaly), 중복 제출된 URL이 표준으로 선택되지 않음(Submitted URL not selected as canonical), 제출된 URL이 noindex·404 등 "제출된 URL" 접두 계열 대부분은 현재 7440203 한국어·영어 본문에 항목으로 나오지 않는다. 구글이 사유를 통합·개편한 것으로 보이나(해석) 공식 문서에서 변경 경위를 확인하지 못했다. 보고서 화면에서 옛 명칭을 만나면 근거 없이 정의를 지어내지 말고 화면의 도움말 링크와 URL 검사 결과를 본다.
- 한국어판에 "제출된 URL이 다른 4xx 문제로 인해 차단됨" 표기가 있다. 영어판 요약에는 "Blocked due to other 4xx issue"만 있다. 제출 여부 표시 차이일 뿐 조치는 같다(URL 검사로 디버깅).
- 한국어판 요약은 "승인 필요(401)" 목록에서 영어판과 같은 조치를 준다. 큰 차이는 확인하지 못했다.

## 5. 색인 생성 요청 도구

- 방법: URL 검사에서 URL 검사 후 "색인 생성 요청". 간단한 사전 검사를 통과하면 대기열 진입. 실시간 테스트에서 색인 불가인 페이지는 요청 불가. (9012289)
- 권한: 속성의 소유자 또는 전체 권한 사용자. 관리하지 않는 URL은 요청 불가. (ask-google-to-recrawl)
- 한도: 개별 URL 제출에 할당량이 있다. 같은 URL을 여러 번 요청해도 더 빨리 크롤링되지 않는다. 검사 횟수, 실시간 검사, 색인 요청 모두 속성별 일일 제한이 있다. 구체 숫자는 문서에 없다. (9012289, ask-google-to-recrawl)
- 소요: 크롤링은 며칠에서 몇 주. 색인 생성은 보통 하루 정도지만 문서에 최대 1~2주라는 표현도 있다. (ask-google-to-recrawl, 9012289)
- 보장 없음: 요청해도 검색결과에 즉시 나오거나 전혀 안 나올 수 있다. (ask-google-to-recrawl)
- 여러 페이지를 바꿨다면 `lastmod`를 넣은 사이트맵 제출이 낫다. 새로 출시했거나 사이트 이전 직후엔 특히. (9012289, ask-google-to-recrawl)
- 호스팅형 CMS(Blogger, WordPress 등)는 대개 플랫폼이 자동 제출한다. (ask-google-to-recrawl)
- 규칙: 크롤링됨/발견됨 - 색인 안 됨 상태에서 같은 URL 요청을 반복하는 것은 효과가 없다고 문서가 시사한다(해석, 문서의 직접 문장은 "여러 번 요청해도 더 빨리 크롤링되지 않음").

## 6. 사이트맵 보고서 상태

| 상태 | 뜻 |
|---|---|
| 성공 | 오류 없이 처리, 모든 URL이 크롤링 대기로 전환 |
| 오류 발생 | 파일은 가져왔으나 오류가 하나 이상. 오류 없이 파싱된 URL은 큐에 들어감 |
| 가져올 수 없음 | 사유 무관하게 파일을 못 가져옴 |

- 제출하면 즉시 가져오기를 시도. 실패하면 며칠 재시도 후 중지. 일시 오류는 몇 시간 뒤에도 계속되면 재제출. 성공한 사이트맵은 주기적으로 재크롤링(주기는 미명시).
- 한도: 파일당 압축 해제 50MB, URL 5만 개, 사이트맵 색인이 담는 사이트맵 5만 개, 뉴스 사이트맵 URL 1,000개. 페이지 500개 이하 사이트는 사이트맵이 필수 아님. 보고서의 제출 요청 표시는 최대 1,000개. (7451001)
